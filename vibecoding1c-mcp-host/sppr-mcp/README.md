# СППР MCP

Компонент ищет и читает текущие данные СППР через четыре инструмента:
`search_sppr`, `read_sppr_object`, `list_sppr_relations`, `sppr_index_status`.
Поиск объединяет точные совпадения, FTS5 и Qwen3 vectors. Реальные связи
читаются отдельными страницами; top-k поиска не является полным обходом графа.
Ответ содержит поколение, время наблюдения, покрытие и native/web ссылки.

## Идеи, дополнительные реквизиты и роли ТП

У идеи сохраняются зарегистрировавший пользователь, источник, тематика,
основание и тип основания. Основание-ссылка включается в граф; чужой объект
остаётся заглушкой без загрузки содержимого. Дополнительные реквизиты ТП и идей
доступны через `read_sppr_object`: свойство и его подпись, значение, тип значения
и текстовая строка. Подписи и содержательные значения участвуют в поиске.
Справочные подписи читаются только по встреченным ссылкам.

Связи идея–шаг содержат `technical_id` строки и `correlation_id` для сопоставления
встречных строк той же пары объектов. Несколько требований между одной идеей
и шагом остаются разными связями; перестановка строк сохраняет их идентичность.
Если в СППР продублирован идентификатор одной и той же связи, сбор сохраняет
предыдущее поколение и сообщает причину. После исправления строк оператором
повторить сбор в разрешённое окно; MCP сам записи источника не исправляет.

Для полной цепочки разработки идеи вызвать:

```json
{"object_id":"Catalog_Идеи:<UUID из поиска>","view":"development","limit":10}
```

Это параметры `list_sppr_relations`; `direction` оставить `both`, фильтр
`relation` не задавать. Читайте `cursor` до `complete=true`.

| `mode` | Значение |
|---|---|
| `same_tp` | ЧТЗ выполняет обе роли: `chtz` и `developer_task` указывают на один ТП. |
| `separate_tp` | Отдельная задача разработчику связана с ЧТЗ через `итлРодитель_Key`; возвращаются обе карточки и ссылки. |
| `unresolved` | Тип/родитель не определён, недоступен в корпусе либо цепочка циклична; причина указана в `issues`. |

Роль берётся из `итлТип.СрезТП`, а не названия типа. Например, «(Эпик)» может
иметь срез `ЧТЗ`. Включение идеи в задачу и родительская цепочка достаточны,
даже если идея перенесена из таблицы ЧТЗ. Несколько задач перечисляются отдельно.
`evidence` содержит ID исходных рёбер; интерпретация ограничена текущим корпусом.
Обычный `view=stored` позволяет последовательно прочитать сами связи и их тексты.

## Размещение и границы

На `dev-ermakov` Docker-контейнер `itl-sppr-knowledge` читает законченные
поколения SQLite из Windows-каталога, смонтированного read-only. Он не имеет
пароля 1С и не запускает сбор. Сборщик — отдельный Python-процесс Windows;
штатная задача `\ITL\ITL SPPR Collector` использует InteractiveToken/ Limited.
Сеанс должен оставаться открытым; отключённый RDP-сеанс допускается.
При выходе пользователя следующий запуск возможен после нового входа в ночное
окно. Задача не использует дневной catch-up, при выходе за окно сбор прерывается.

Начальный allowlist: `76bcfc1f-e8c2-4cd6-80ef-997b99bca476`
(«Кейс проект PM5»). Все клиенты имеют одинаковый доступ к этому корпусу.
Источник читается стандартной авторизацией 1С через OData, без записи.
В OpenRouter поступают только разрешённые тексты и согласованные поисковые
запросы. Вложения и внешние карточки Mantis/ДО не загружаются.

## Подготовка хоста

Исходники компонента поставляются вместе с каталогом MCP Host в workflow.
В установленный проект попадает поддержка клиентского подключения; сборщик
и секреты остаются на выделенном хосте. Развёртывание и первый сбор выполняются
на отдельном этапе приёмки из OpenSpec.

1. Создать внешний каталог компонента, например `D:\ITL\MCP\sppr`.
   Скопировать `config.example.json` в `collector.json`, проверить адрес
   публикации, native/web базы, окно и часовой пояс.
   `state` указывает на `state`, `policy` — на соседний `public\policy.json`.
   Скопировать проверенный `policy.example.json` в этот путь.
2. В отдельном защищённом файле `secrets\collector.json`, вне Git и вне
   `state/public`, разместить JSON с `username`, `password`, `api_key`.
   Первые два значения — учётная запись 1С, последнее — ключ OpenRouter.
   Ограничить чтение файла пользователем сборщика средствами текущего хоста.
   Секреты не передаются аргументами процесса.
3. В локальном `host.config.json` задать `spprServer.configPath` и
   `spprServer.credentialPath`; добавить `sppr` в `enabledServers.global`
   и `toolsListProxy.serverIds`. Задать `secrets.SPPR_EMBEDDING_KEY` для
   векторов запросов контейнера. Используется отдельный embedding-профиль
   компонента; общую настройку `embedding` других MCP менять не требуется.
4. В каталоге MCP Host выполнить:

```powershell
.\install-vibecoding1c-mcp-host.ps1 -Action setup -ConfigPath .\host.config.json -ServerId sppr
.\install-vibecoding1c-mcp-host.ps1 -Action sppr-collector-install -ConfigPath .\host.config.json
```

`setup` подготавливает отдельный venv, проверяет конфигурацию, строит образ,
монтирует только `state/public`, запускает MCP и публикует endpoint в существующий
реестр. Сбор сам по себе не запускается. До первого завершённого сбора
`sppr_index_status` отвечает `unavailable` с инструкцией продолжения.
Подготовку runtime без контейнера выполняет `-Action sppr-prepare`.
Компонент требует Python 3.12+ на Windows и Linux Docker engine.

После появления endpoint обновлённый workflow обнаруживает логический сервер
`sppr` и клиентское имя `sppr-knowledge` через общий реестр.
Штатный `vibecoding1c-mcp-setup` предлагает его вместе с другими серверами.
Для уже установленного проекта: `vibecoding1c-mcp-refresh-registry`, затем
`vibecoding1c-mcp-select -McpServerId sppr -McpProvider remote -McpHostId dev-ermakov`
и `vibecoding1c-mcp-write-client-config` через helper проекта.
Подключение использует опубликованный URL; порт не зашит в workflow.
После первой записи конфигурации клиенту требуется перечитать MCP.

## Сбор и восстановление

Примеры выполняются на хосте из каталога `sppr-mcp` в открытом сеансе:

```powershell
$spprPython = 'D:\ITL\MCP\sppr\runtime\Scripts\python.exe'
$spprConfig = 'D:\ITL\MCP\sppr\collector.json'
$spprCredentials = 'D:\ITL\MCP\sppr\secrets\collector.json'
& $spprPython -X utf8 -B .\collector.py status --config $spprConfig
& $spprPython -X utf8 -B .\collector.py collect --config $spprConfig --credentials $spprCredentials
& $spprPython -X utf8 -B .\collector.py embed-pending --config $spprConfig --credentials $spprCredentials
```

`collect` выполняет ночную ID/version сверку и адресные чтения.
Дневной первый полный сбор требует явного операторского `--outside-window`;
в расписание этот флаг не включён. Фильтруемый журнал изменений не подтверждён,
поэтому обещания обновления за 15 минут нет.
Все выбранные табличные части перечитываются каждую ночь, даже если
`DataVersion` карточки не изменился. Общие LCM-зависимости проверяются по своим
версиям. Неизменённые совместимые векторы переиспользуются по хешу текста.

При отказе OData, нестабильной пагинации, смене политики или сеанса новый
снимок не активируется. При отказе OpenRouter завершённый сбор публикует
лексические данные с неполным semantic coverage; `embed-pending` дозаполняет
векторы из сохранённого корпуса без повторного OData scan.
Кеш векторов запросов — LRU в памяти, по умолчанию 256; результаты поиска
не кешируются. Совместимый кешированный запрос работает и при отказе provider,
новый запрос деградирует до точного/лексического поиска.

Allowlist изменяется атомарной заменой `public\policy.json` с массивом UUID
`projects`. Отзыв проекта действует до следующего сбора: новые выдачи и
отправки embeddings проверяют текущий файл. Уже отправленный пакет отозвать
нельзя. Добавленный проект появится после успешного сбора. Общий LCM-объект
остаётся, пока у него есть хотя бы один разрешённый путь включения.

`state/active.json` указывает на завершённое поколение. Сохраняются последние
три поколения; открытый Windows-читатель может временно отложить очистку.
Для отката передать существующий идентификатор файла `<generation>.sqlite`:

```powershell
& $spprPython -X utf8 -B .\collector.py rollback --config $spprConfig --generation '<generation>'
```

Откат проверяет целостность и источник, но не восстанавливает старый allowlist.
Не удалять lock-файл: OS-lock освобождается при завершении процесса.
Для отключения компонента: `-Action sppr-collector-uninstall`, затем
`-Action stop -ServerId sppr` с тем же `ConfigPath`.
Сохранённые данные и другие MCP не удаляются.

При смене размерности, инструкции запросов, chunking или provider база
перестаёт использовать старое пространство vectors. После `sppr-prepare`
нужно выполнить `-Action stop -ServerId sppr`, затем `-Action start -ServerId sppr`
с тем же `ConfigPath`, и `embed-pending` либо очередной сбор.
Модель разрешённого профиля — `qwen/qwen3-embedding-8b`, размерность по умолчанию
4096. Доступность модели и реальные usage проверяются при host-приёмке.

## Покрытие источника

Карта проекций живёт в `sppr_core.py`, типы ссылок берутся из `$metadata`.
Подтверждены 11 типов и 16 табличных частей текущей публикации:

| Объекты | Допуск / данные |
|---|---|
| ТП, идеи, процессы, разделы, системные функции, целевые задачи | Владелец — разрешённый проект |
| Шаги процесса | Владелец — включённый процесс |
| Протоколы | Реквизит Проект — разрешённый проект |
| Решения, проблематики, функциональные решения LCM | Явный исходящий путь из допустимой карточки |
| Статусы, пользователи, типы, спринты, роли, исполнители | Только адресное получение представления; без рекурсивного обхода |

Поля включают доступные статусы, разработчика/тестирующего, тип, оба спринта,
Mantis, описания/заметки; строка ТП–идея хранит собственную реализацию/комментарии.
Незаполненные поля, неприменимые реквизиты и ошибки извлечения различаются.
FormattedDocument обрабатывается без выполнения XML/entities; неизвестный
формат виден как unreadable. Незаполненная ссылка не удаляет текст строки.
`coverage` относится к опубликованному поколению; `visible_objects` —
к текущему allowlist. UUID-ссылки на чужие объекты не раскрывают их тексты.

Генератор использует внутренний формат [ссылок платформы 1С](https://kb.1ci.com/1C_Enterprise_Platform/Guides/Developer_Guides/1C_Enterprise_8.3.23_Developer_Guide/Appendix_1._URL_formats/1.2._Internal_links/1.2.2._Infobase_objects_links/?language=en)
и пользовательский эталон. Открытие всех типов в двух клиентах проверяется
отдельно; успешный HTTP ответ веб-публикации этого не доказывает.

## Локальная проверка исходников

Из корня workflow создать отдельный venv и установить зависимости компонента:

```powershell
python -m venv build/sppr-venv
build/sppr-venv/Scripts/python.exe -m pip install -r vibecoding1c-mcp-host/sppr-mcp/requirements.txt
build/sppr-venv/Scripts/python.exe -X utf8 -B -m unittest discover -s vibecoding1c-mcp-host/sppr-mcp -p 'test_*.py'
```

Pester владельца выбирает этот runtime либо `SPPR_TEST_PYTHON`.
Фикстуры не содержат рабочих карточек и не обращаются к OpenRouter.
Реальный HTTP MCP проверяется двумя клиентами, Windows-пути — с кириллицей
и пробелами через штатный процессный транспорт хоста.
Статус всех локальных и ещё не выполненных host-сценариев:
[план приёмки](../../openspec/changes/add-sppr-knowledge-mcp/test-plan.md).
