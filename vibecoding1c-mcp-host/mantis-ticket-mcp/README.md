# Mantis MCP: поиск, чтение и управляемая запись

Состояние реализации и доказательства: [OpenSpec test-plan](../../openspec/changes/extend-mantis-mcp-search-and-write/test-plan.md).
Исходники подготовлены для MantisBT 2.28.1; сервер Mantis не изменяется.
Индекс и запись по умолчанию выключены. Локальные fixtures не заменяют проверку
Docker-образа, прав на тестовом Mantis и canary с реальными объёмами.

## Подключение и конфигурация

Настройки находятся в `mantisTicketServer` локального `host.config.json`.
Токены хранятся в его `secrets`, вне Git. Для отдельной разрешённой установки
используется существующий [установщик хоста](../README.md) с `-ServerId mantis`.
Десять инструментов требуют одновременно соответствующего Mantis-образа
и обновлённого `tools-list-proxy/tools-contract.json`; старый контракт на три
инструмента закономерно не пройдёт readiness.

| Настройка | Переменная контейнера | Значение по умолчанию / назначение |
| --- | --- | --- |
| `statePath` | `MANTIS_STATE_PATH=/data/mantis` | Отдельный постоянный каталог Mantis для SQLite и Zvec |
| `attachmentCachePath` | `MANTIS_ATTACHMENT_CACHE_PATH=/data/attachments` | Прежний отдельный кэш оригинальных файлов |
| `indexEnabled` | `MANTIS_INDEX_ENABLED` | `false`; `true` запускает первичную загрузку доступных проектов |
| `syncIntervalSeconds` | `MANTIS_SYNC_INTERVAL_SECONDS` | `30`; пауза между проходами работника |
| `syncProjectIds` | `MANTIS_SYNC_PROJECT_IDS` | `[]` означает все доступные; для canary задать ID одного проекта |
| `monthlyBudgetUsd` | `MANTIS_MONTHLY_BUDGET_USD` | `5`; календарный месяц UTC, включая поисковые эмбеддинги |
| `writeEnabled` | `MANTIS_WRITE_ENABLED` | `false`; общий выключатель записи на время обслуживания |
| `attachmentExtractEnabled` | `MANTIS_ATTACHMENT_EXTRACT_ENABLED` | `false` при поставке; включает отдельный ограниченный работник извлечения текста |
| `secrets.MANTIS_API_TOKEN` | `MANTIS_API_TOKEN` | Общая служебная учётная запись |
| `secrets.MANTIS_OPENROUTER_API_KEY` | `MANTIS_OPENROUTER_API_KEY` | Необязательный отдельный ключ; без него доступен текстовый поиск |

Все допущенные к MCP сотрудники видят всё доступное служебной учётной записи,
включая закрытые и разрешённые приватные источники. В профиле клиента задаётся
HTTP-заголовок `X-Mantis-Actor: <имя или логин>`. Это заявленная личность внутри
доверенной группы, а не персональная авторизация в Mantis. Новые инструменты
также принимают `actor`; при включённом индексе прежние read tools используют
заголовок, сохраняя прежние аргументы. Поля initiator/operation добавляются в
создаваемые и изменяемые тексты; изменение только статуса не добавляет комментарий.

Модель закреплена: `qwen/qwen3-embedding-8b`, 4096 измерений, фрагменты до 1800
символов с перекрытием 180. Зависимости: FastMCP 2.14.7, MCP SDK 1.30.0, Zvec 0.7.0, NumPy 2.2.6;
SQLite берётся из Python и должен поддерживать FTS5 и JSON-функции. Полный исходный текст и
исходные имена файлов индексируются отдельно от обрезанного ответа reader.
Текстовый слой PDF, DOCX и XLSX индексируется отдельным работником после включения
`attachmentExtractEnabled`. Изображения, сканы без текстового слоя и OCR в поисковый
индекс не попадают. Статусы и количество файлов по категориям видны в
`index_control(action="status")` → `attachment_extraction`.
На файл действуют пределы: 5 МиБ исходных байтов, 50 МиБ распакованного ZIP,
40 страниц PDF, 2000 абзацев/20 таблиц DOCX, 20 листов/20 000 ячеек XLSX,
100 000 извлечённых символов и 20 секунд работы парсера с лимитом памяти 512 МиБ.
Выход за предел помечается `partial` или `too_large`; `unsupported` и `failed`
не считаются полным покрытием. Если Mantis возвращает метаданные файла без его
байтов, статус `source_unavailable` показывает пробел покрытия и повторяет
проверку через сутки. Даже при наличии записи вложения файл на диске Mantis
может отсутствовать; поиск по его содержимому тогда невозможен до восстановления
источника. Исходные байты извлекатель не сохраняет.

## Компактный поиск и продолжение

`search_tickets` возвращает по умолчанию **10 карточек**, максимум 20 за вызов,
но вся структурированная страница ограничена **12 000 символами**. У карточки
не более трёх совпадений по 280 символов. Чрезмерно длинное имя (>1000 символов)
в карточке обозначается `filename_truncated`; поиск использует полное имя.
Полные тексты комментариев, оригиналы и весь журнал автоматически не выдаются.
Текстовый MCP-блок содержит лишь короткую сводку, без второй копии JSON.

```json
{"query":"ошибка при закрытии месяца","actor":"analyst","limit":10}
```

Без фильтра рассматриваются все доступные проекты и статусы. `mode` принимает
`all`, `comments`, `filenames`, `attachment_contents`. Совпадение внутри файла
содержит `file_id`, имя, координату страницы/абзаца/ячейки, краткий фрагмент и
`file_url`; `filenames` ищет только по именам. Фильтры: `project_id`, числовой `status`, список
`tags` (ID или имена), `custom_fields` (ID → значение, вместе с проектом),
`created_after/before`, `updated_after/before` (ISO 8601 с timezone),
`handler_id`, `reporter_id`, числовые `priority`/`severity`, точные строки
`version`, `target_version`, `fixed_in_version`. `sort_by` задаёт порядок:
`relevance` (по умолчанию), `updated_at` или `created_at`, с ID для равенства.
`mantis_metadata(project_id=...)` выдаёт определения полей и ограничения проекта.
`mantis_metadata(project_id=..., participants_query="Иван")` ищет участников проекта
по имени и логину порциями по 10 (максимум 20) с `participant_cursor`;
`handlers_only=true` ограничивает список доступными исполнителями. Неоднозначное
имя разрешается выбором конкретного ID. Имя инициатора MCP не доказывает
личность учётной записи Mantis.
Неизвестный фильтр не игнорируется. Пустой запрос даёт такую же ограниченную
страницу обзора, а не выгрузку базы.

Для следующей страницы передать выданный `next_cursor` вместе с теми же
`query`, `filters`, `mode`, `semantic`, `sort_by`. Курсор продвигается на реально выданные
карточки, даже если предел символов сработал раньше `limit`. Самостоятельно
выгружать все страницы при широком запросе не требуется: сначала уточнить отбор.
При изменении найденных источников во время перепроверки ответ `results_changed`
просит повторить поиск; импорт постороннего обращения сам по себе выдачу не
сбрасывает. Курсор по-прежнему привязан к ревизии индекса: при её изменении поиск
повторяется без курсора. Окно кандидатов ограничено; `candidate_window_limited=true`
означает необходимость сузить запрос для более полного отбора.

`semantic=false` исключает платный эмбеддинг самого запроса. `semantic_query`
и `semantic_corpus` сообщают состояние запроса и покрытия базы отдельно.
Вектор точного текста запроса переиспользуется между страницами, фильтрами и
повторными вызовами. В памяти процесса хранится LRU-кэш последних 256 векторов
(около 8 MiB векторов по 4096 чисел double), с ключом из профиля модели и хеша
точного входного текста. Одновременные одинаковые запросы делят один вызов
OpenRouter и один резерв расходов; ошибки в кэш не попадают. Перезапуск процесса
очищает этот кэш, на диск тексты запросов/их векторы не записываются. Результаты
и права не кэшируются этим механизмом: поиск идёт по текущему индексу и проверяет
найденные обращения. `query_embedding_cache` сообщает `hit/miss/shared`, а
`health`/`index_control(status)` показывают заполнение и счётчики кэша.
`read_ticket` и `get_attachment` сохраняют прежнее подробное чтение и MCP image
content. Для компактного чтения используйте `read_ticket(include_comments=false)`
и `read_comments(url_or_id, note_id=0, direction="newest", limit=10, cursor="")`.
Он выдаёт максимум 20 комментариев и 12000 символов за вызов; `note_id` открывает
конкретное совпадение из поиска, а `next_cursor` продолжает страницу или длинный
текст. Курсор привязан к содержимому обсуждения этого обращения. При его изменении
инструмент возвращает `discussion_changed` и требует начать чтение заново.
`index_control(status, detail=true)` показывает безопасную категорию и время
последней ошибки эмбеддингов, число последовательных сбоев и следующий повтор.
Резерв расхода после неизвестного результата OpenRouter остаётся в журнале;
текст запроса и ключ в диагностике не выводятся.

`ticket_history(url_or_id, from_date="", to_date="", kinds=[], limit=10,
cursor="")` возвращает историю полей одного доступного обращения по 10 событий
(максимум 20) и до 12000 символов. Поддержаны видимые поля обращения, включая
статус и исполнителя; события о комментариях, файлах и неразрешённых полях
исключаются на Mantis 2.28.1, их количество обозначено
`omitted_unverified_events`. Это история Mantis, отдельно от журнала MCP.

`search_tickets(similar_to=123)` ищет по заголовку (до 240 символов), описанию
(до 900) и шагам (до 400) доступного обращения; сам источник исключён. Параметр
`query` при этом оставляют пустым. Ответ указывает `similarity_mode=semantic`
или `lexical_fallback`: совпадение не является доказанным дубликатом.

## Загрузка и свежесть

Mantis включает подпроекты в страницы родительского проекта. При синхронизации
сохраняются исходная длина, порядок и подпись страницы, но загружаются только
обращения самого проекта; подпроекты проходят свой импорт со своими правами.
Страница, целиком занятая подпроектами, не означает конец выборки.

Checkpoint у каждого проекта относится **только к дате изменения**
`updated_at/last_updated`. `created_at` используется лишь как явный фильтр поиска.
Новый проект получает возобновляемый полный импорт и компактную сверку всех
ID/дат до двух совпадающих проходов, затем догоняющую дельту. Это защищает от
пропуска старого неизменённого обращения при смещении страниц первичного импорта.
В текущем режиме читается лишь недавнее окно заголовков с перекрытием 300 секунд;
полнота проверяется повторно до продвижения checkpoint. Незавершённая порция
сохраняет прогресс и продолжает на следующем цикле. Истёкший бюджет попытки не
объявляет проект свежим. HTTP `Date` используется лишь для прекращения повторных
GET неизменённых старых объектов вне перекрытия, а не вместо даты изменения.

Первичный импорт также ограничивает время одной порции. Продолжение внутри
неизменённой страницы хранится в памяти; при изменении её видимого содержимого
или перезапуске страница безопасно перечитывается. Checkpoint и номер страницы
продвигаются только после её завершения. Эмбеддинги догоняют новые тексты между
проектами, не ожидая окончания первичного импорта всей базы.

Блокирующие инструменты исполняются вне HTTP-потока, с сохранением MCP-контекста
инициатора. Новые фрагменты не сканируют FTS для удаления отсутствующей записи;
старые удаляются порциями по FTS rowid. Формат SQLite v1 сохраняется, перестройка
индекса и повторная покупка эмбеддингов для этого обновления не нужны. Совместимые
индексы по типу источника, ID вектора, очереди эмбеддингов и версиям обращений
создаются при открытии прежней базы. Поиск читает поля карточки и фильтров один раз
на обращение, без полных комментариев. После проверки Mantis сравниваются версии
источников; повторного чтения всех текстов для той же страницы нет.

Цель до 300 секунд для обычных изменений после первичного наполнения ещё требует
canary. Долгая нестабильная пагинация, первичная загрузка, недоступный OpenRouter
или исчерпанный бюджет показываются как задержка/неполная семантика.
Смена приватности комментария, удаление файла, переименование метки и отзыв прав
могут не менять дату обращения. Найденные и открываемые обращения перечитываются,
каталоги проверяются отдельно. Новое видимое содержание без изменения даты не
гарантированно обнаруживается до такого перечитывания.

При недоступном Mantis кэш выдаётся без TTL, с `access_check`/`last_verified`.
Timeout, 5xx и ошибка аутентификации не удаляют данные. Подтверждённый запрет или
удаление убирает текст из SQLite/FTS и выдачи; работник физически удаляет старые
поколения векторов, файлы и содержательные части журнала. Остаются ID, инициатор
и результаты шагов. Новое получение доступа требует нового чтения Mantis.

## Матрица записи на 2.28.1

Все маршруты сейчас выключены общим выключателем в поставляемой конфигурации.
После проверки на тестовом контуре его можно включить один раз; списков действий
и проектов в конфигурации больше нет. Права считываются заново перед каждым шагом;
HTTP 200 не заменяет проверку.

| Действие | Маршрут | Независимые проверки |
| --- | --- | --- |
| `create_issue` | REST POST issues | report threshold; summary/description; required/custom-field constraints |
| `update_issue` | REST PATCH issue | update/readonly; status threshold + workflow + reopen; assignment/view-state; custom fields; full ETag |
| `add_comment` | REST POST notes | add-note; privacy; при files также upload threshold/тип/размер |
| `update_comment` | SOAP `mc_issue_note_update` | числовой own-note либо other-note threshold; видимый note, текст и privacy |
| `upload_file` | REST POST issue files | доступный parent, upload threshold, размер/расширение, сверка байтов |
| `attach_tag` / `detach_tag` | REST issue tags | существующий ID; attach/full detach threshold; результат перечитывается |
| `attach_relationship` / `detach_relationship` | REST issue relationships | обновление исходного обращения, видимость обоих обращений, точный ID и тип связи, версия и обратное чтение |

Для всех действий требуется как минимум reporter и применимые проектные пороги,
включая readonly. Поддерживаемые поля issue перечислены в `mantis_write.ISSUE_FIELDS`;
прочие поля отклоняются до отправки. Значения custom fields сверяются с definitions,
правами, required/length/possible-values и поддерживаемой regex; типовые серверные
ограничения дополнительно подтверждаются post-read. Динамические варианты и
сложные PCRE-конструкции не квалифицированы. Только более низкий own-tag-detach
threshold пока не поддерживается: нужен полный `tag_detach_threshold`.
Добавление файла к уже существующему комментарию недоступно; скрытой подмены
на вложение обращения нет. Удаление issue/note/file не реализовано.

Конкретная команда пользователя разрешает вызов `execute_write`; подготовка
черновика сама по себе такого вызова не допускает. Пример после явной команды:

```json
{"operation_id":"analyst-20260928-001","actor":"analyst","steps":[
  {"action":"add_comment","issue_id":123,"fields":{"text":"Проверено на тестовой базе"}}
]}
```

Для изменения существующих полей/текста сначала вызвать
`write_operation(action="inspect", issue_id=123)` и передать его
`expected_version` в шаге. Inspect выдаёт версию и краткие поля, без всех текстов
комментариев. MCP сериализует все собственные записи; pre/post-read
и If-Match, где доступен, обнаруживают известные конфликты. Окно гонки с UI Mantis
остаётся. Ни SOAP, ни REST 2.28.1 не объявляются атомарным CAS.
Связи используют `related_issue_id` и `relationship_type` со значениями
`related-to`, `duplicate-of`, `parent-of`, `child-of`; удаление требует
`relationship_id` из `read_ticket` и того же `related_issue_id`. Изменение
существующей связи также требует `expected_version`.

## Прерывания, расходы и восстановление

Повторять прерванную составную команду следует с прежними `operation_id`,
`actor` и неизменным `steps`: успешные шаги не повторяются. Один ID принадлежит
одному обращению и одному payload. `write_operation(action="status")` показывает
подтверждённые ID. `cancel` запрещает дальнейшие шаги, сохраняя уже выполненные;
in-flight результат требует сверки. Для новой команды после cancel использовать
новый ID и только оставшиеся действия.

`unknown/partial` автоматически сверяется с Mantis; неоднозначный POST никогда
не повторяется вслепую. `resolve` принимает номер шага с нуля и явный исход
`applied` (при необходимости `server_id`) или `not_applied`. Применённый исход
дополнительно проверяется. Доказанно созданный объект нельзя объявить отсутствующим
ради повтора. Если note создан, а файл при нём не подтверждён, сохраняется note ID;
отдельно разрешается сверка файла либо новая команда для вложения issue/нового note.
Автоматического удаления опубликованного нет.

`index_control(action="status")` показывает проекты, ошибки, очередь эмбеддингов,
незавершённую очистку, возраст каталогов и расходы. `pause` останавливает новые
фоновые порции; текущий запрос заканчивается в пределах своего timeout.
`resume` продолжает их. Пауза сохраняется в SQLite и переживает перезапуск.
При обновлении ранее созданного индекса без этого поля новый образ начинает
работу на паузе; после проверки диска и миграции снимите её явным `resume`.
`embedding_spooled` показывает оплаченные и сохранённые в SQLite векторы,
ожидающие пакетной записи Zvec. Пакет до 512 векторов сбрасывается на диск
целиком до отметки `vector_version`; неполный пакет сбрасывается после 60 секунд
или по завершении очереди. При сбое после сохранения пакета в SQLite повторный
запрос OpenRouter для него не нужен. Короткое окно между ответом провайдера и
сохранением в SQLite остаётся неопределённым для повторной оплаты.

`index_control(action="storage")` по запросу считает файлы и байты текущего
поколения Zvec и показывает свободное место на томе, видимое из контейнера.
`compact_vectors` требует `pause` и `work_in_progress=false`: переносит только
актуальные векторы в новое поколение без вызовов OpenRouter, повторно открывает
и проверяет его перед переключением, затем удаляет старое поколение. Перед
операцией нужно учесть временное место под оба поколения. Обычный поиск не
обходит файлы для этого измерения.

`rebuild_vectors` восстанавливает только векторную проекцию из актуальной SQLite.
Сначала `pause`; если есть текущая работа, дождаться `work_in_progress=false` и
повторить команду. Журнал, tombstone, тексты и бюджет сохраняются. После `resume`
недостающие эмбеддинги могут оплачиваться в пределах настроенного бюджета.
Неудалённое старое поколение отмечается как pending cleanup; лексика продолжает
работать, а выдача проверяет актуальную SQLite-версию каждого vector hit.
При откате на образ без сохраняемой паузы установите паузу повторно сразу после
запуска. Дополнительная таблица `embedding_spool` не меняет номер SQLite schema 1;
старый образ её игнорирует. Возврат старого образа во время непустого пакета
допускается только после завершения пакетной записи новым образом: иначе старый
индексатор может повторно заказать сохранённые, но ещё не опубликованные векторы.

Каждый запрос OpenRouter резервирует верхнюю оценку расходов до отправки;
применяется ограничение цены провайдера. Неизвестный итог, в том числе отсутствие
cost в успешном ответе, остаётся резервом и переносится через границу месяца.
После сверки счёта оператор вызывает `settle_charge` с `charge_id` и подтверждённым
`actual_cost_usd`; значение 0 допустимо лишь для доказанно нетарифицированного вызова.
При достижении лимита сохраняются текстовая загрузка, лексика и фильтры.

SQLite schema v1 использует DELETE journal и secure_delete; `owner.json` и OS-lock
не дают второму процессу открыть тот же volume. Неподдерживаемая схема/profile
отключает новые возможности, оставляя прежнее прямое чтение. Не удалять lock-файл
и не подменять owner marker; остановить лишний экземпляр или вернуть совместимый
образ. Подключение чужого непустого каталога отклоняется.

Откат: остановить новые команды, сверить in-flight/unknown, отключить
`indexEnabled`, оставить оба Mantis volume и вернуть совместимое прямое чтение.
Откат образа согласовывается с его proxy contract. Не восстанавливать старую SQLite
поверх последних journal/budget/revocation. Штатного восстановления целой БД из
устаревшего snapshot нет; пересоздавать разрешено производную векторную проекцию
из текущего состояния. Code, BookStack и lifecycle 1С для этого не перезапускаются.
