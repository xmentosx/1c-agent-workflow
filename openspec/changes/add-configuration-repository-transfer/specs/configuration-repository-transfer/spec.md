## Purpose

Переносит проверенные изменения основной конфигурации из ветки в хранилище 1С с возможностью проверить весь результат в подключённой базе до помещения.

## ADDED Requirements

### Requirement: Выбор ответственного за просмотр

Workflow SHALL предоставить две команды в ветке основной конфигурации с хранилищем. Обе работают с существующей подключённой ИБ и одним составом переноса. Просьба о помещении без уточнения выбирает ручной просмотр, явное поручение выполнить самостоятельно выбирает автоматический.

#### Scenario: Ручной и автоматический путь

- **WHEN** пользователь запускает `/itl-repository-commit-review`
- **THEN** до объединения он получает доступное для изучения сравнение и может принять результат целиком или вернуть его в ветку с замечаниями. После принятия агент продолжает по исходному поручению.

#### Scenario: Обычный автоматический перенос

- **WHEN** пользователь запускает `/itl-repository-commit-auto`, состав полностью понятен и все этапы проходят
- **THEN** агент изучает сравнение, объединяет, обновляет ИБ, выполняет дымовую проверку и сообщает номер созданной версии без промежуточного запроса одобрения.

### Requirement: Захват всех необходимых объектов и проверка CF

Перенос MUST выполнить штатный захват до обновления ветки и сверить набор после разрешения конфликтов. Экспортируемый итог MUST соответствовать свежей успешной проверке после последнего изменения, манифесту и SHA-256 предъявленного CF.

#### Scenario: Частичный захват и отмашка

- **WHEN** хотя бы один необходимый захват занят другим пользователем
- **THEN** агент останавливается до следующего этапа, перечисляет каждый занятый объект с владельцем и сохраняет полученные захваты. После отмашки человека повторяет захват. При подтверждённом успехе операции запрошенный объект без отдельной строки и конфликта считается уже захваченным текущим пользователем. Оборванный журнал оставляет исход неизвестным.

#### Scenario: Итог после обновления ветки

- **WHEN** обновление потребовало совместить правки ветки и хранилища
- **THEN** агент объясняет и проверяет сохранение требований обеих сторон, при несовместимых требованиях запрашивает решение. Он дозахватывает новые необходимые объекты до сравнения. Выпавшие объекты исключает из помещения и сохраняет предшествующие переносу захваты пользователя.

#### Scenario: Проверка после доработки

- **WHEN** изменилась ветка, проверка частична или CF расходится с манифестом
- **THEN** агент возвращается к штатной проверке и экспорту до применения CF. Пересобранный CF требует нового просмотра в выбранном режиме.

### Requirement: Полный состав переноса и решение по нему

Сравнение SHALL показывать результат объединения с разрешённым удалением в подключённой ИБ и полный итог задачи относительно актуального хранилища. Перед применением и помещением workflow MUST удостовериться, что актуальны цель и рассмотренный состав и в операцию входят только изменения задачи.

#### Scenario: Деталь формы и код

- **WHEN** CF удаляет реквизит формы и меняет обработчик
- **THEN** просмотр показывает удаление с именем реквизита и изменения строк обработчика. Для недоступной детали человеку предоставляется штатное сравнение конкретного объекта. Если агент не может оценить деталь сам, он показывает её человеку и ждёт решения.

#### Scenario: В базе есть чужая работа или изменился результат

- **WHEN** обнаружены посторонние незавершённые изменения либо во время ожидания изменился состав переноса
- **THEN** агент показывает посторонние изменения и передаёт решение человеку. Изменившийся состав предъявляется заново. До решения прежнее одобрение не разрешает объединить изменившийся результат или включить чужую работу.

### Requirement: Дымовая проверка в обновлённой ИБ

После объединения и обновления конфигурации базы данных агент SHALL выполнить один короткий пользовательский сценарий, проверяющий ожидаемый эффект задачи в подключённой ИБ. По умолчанию результаты ветки используются без повторения полного набора тестов.

#### Scenario: Проведение документа

- **WHEN** задача меняет движение при проведении и в ИБ есть пригодные тестовые данные
- **THEN** агент проверяет конкретное ожидаемое движение. Если безопасный эквивалент сценария недоступен, агент сообщает отдельно доказательства из ветки и из подключённой ИБ и передаёт решение о помещении человеку.

#### Scenario: Доработка после неудачной проверки

- **WHEN** сценарий обнаружил ошибку после применения первого CF
- **THEN** помещение останавливается, сохраняются захваты и результат проверки. Исправление выполняется в ветке без автоматического отката общей ИБ. После повторной подготовки просмотр охватывает также изменения первого CF, уже применённые в подключённой ИБ. Дымовой сценарий проверяет исправленный результат.

### Requirement: Подтверждение версии и завершение в Mantis

Помещение SHALL создавать версию только из согласованных изменений с комментарием `номер обращения: заголовок` для обращения Mantis или кратким описанием задачи без обращения. Подтверждённая версия завершает перенос. Агент MUST отличать этот результат от состояния последующей записи в Mantis.

#### Scenario: Связь прервалась в момент помещения

- **WHEN** неизвестно, создал ли Конфигуратор версию
- **THEN** агент сверяет историю и фактический состав. Однозначно найденную версию сообщает без повтора. Повтор разрешён после подтверждения отсутствия помещения. При неоднозначности показывает кандидатов человеку. Совпадения текста комментария недостаточно.

#### Scenario: Полное и частичное выполнение обращения

- **WHEN** версия подтверждена и обращение известно
- **THEN** агент записывает выполненные пункты, переводит обращение в «Решено» только при выполнении всех пунктов и сохраняет текущий статус при частичном результате. Без обращения действие в Mantis пропускается.

#### Scenario: Прервалась запись в Mantis

- **WHEN** версия создана, но комментарий или статус остались неподтверждёнными
- **THEN** агент сообщает номер версии, сверяет уже записанное и продолжает только оставшуюся операцию без повторного помещения или дублирования комментария.
