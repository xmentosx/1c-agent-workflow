# Помещение изменений основной конфигурации в хранилище 1С

## Why

Сегодня разработчик получает проверенный CF в ветке, затем вручную сравнивает его с подключённой ИБ, проверяет результат в пользовательском режиме и помещает изменения. Требуется делегировать этот цикл агенту, сохранив возможность увидеть вносимые в базу изменения до объединения. [Действующий цикл](../../../docs/itl-workflow/PROJECT-WORKFLOW.ru.md) · [Согласованные решения](../../../docs/adr/0008-configuration-repository-transfer-review.md)

## What Changes

- Две команды ветки ведут один перенос. `/itl-repository-commit-review` останавливается для просмотра человеком. `/itl-repository-commit-auto` поручает агенту принять решение по тому же сравнению.
- Перенос связывает захват, обновление ветки и разбор конфликтов, проверенный CF, сравнение с удалениями, объединение, обновление подключённой ИБ и короткую проверку до помещения.
- Успех подтверждается конкретной версией хранилища. Для известного обращения агент сообщает в Mantis результат по пунктам и завершает только фактически выполненную работу.

## Capabilities

### New Capabilities

- `configuration-repository-transfer` — помещение основной конфигурации из ветки в хранилище, просмотр человеком или агентом и продолжение после прерывания.

## Impact

Затронуты команды ветки установленных клиентов, lifecycle ITL, подключённая к хранилищу ИБ, Конфигуратор и при наличии обращения действующий интерфейс записи Mantis. Первая версия охватывает CF. Для приёмки нужны отдельное тестовое хранилище с подключённой ИБ и подходящими данными, подтверждение возможностей платформы и проверка пользовательского сценария обоими входами.
