# Проверка поиска в содержимом вложений

Источник контрольных данных: помеченные обращения в проекте «Прототипы» (397),
который пользователь разрешил использовать; тестовые обращения и файлы можно оставить.
Сохранить отдельные уникальные фразы в PDF с текстовым слоем, DOCX и XLSX.

| Проверка | Ожидаемое свидетельство | Состояние |
| --- | --- | --- |
| Локальные parser/worker/search tests | Координаты трёх форматов, ограничения ZIP/скана, перезапуск и отсутствие повторного извлечения | index, server и parser tests прошли локально; image test впереди |
| Совместимость состояния | Старый и новый образы открывают копию SQLite; журнал записи не исчезает | Не проверено |
| Поставка с выключенным извлечением | Тот же direct endpoint, 10 tools, read/search/write, тома и соседние MCP | Не проверено |
| Контрольная PDF/DOCX/XLSX | `mode=attachment_contents` находит по уникальной фразе каждое вложение с file ID и страницей/абзацем/ячейкой | Не проверено |
| Ограничения и отказ | Неподдерживаемый формат/скан/превышение лимита показывает точный статус без ложного покрытия | Не проверено live |
| Доступ и удаление | После подтверждённого исчезновения файла/приватного note производный текст и вектор не выдаются; временный сбой Mantis оставляет кэш | Локально проверено удаление файла и приватного note-фильтр; live не проверено |
| Бюджет и прогресс | Лексический поиск работает при сбое OpenRouter; очередь и $5 общий лимит видны, индекс основной базы продвигается | Не проверено |
| Откат | Выключение извлечения сохраняет основной индекс, журнал записи и рабочий MCP; прежний образ доступен | Не проверено |

Приёмка не объявляется завершённой по одному successful build. Для live каждого
файла зафиксировать ID обращения, ID файла, наблюдаемые результаты поиска,
статус worker, свободное место и длину очереди до и после. Пауза/возобновление
учитывают оба работника. В режиме кэша следует явно показывать свежесть, как в
основном поиске.
