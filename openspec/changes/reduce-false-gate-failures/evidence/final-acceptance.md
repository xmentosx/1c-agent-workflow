# Сверка с аудитом отказов

Проверка 12 ноября 2026 года по [аудиту](failure-audit.md), записям в общем `.git/itl/runs`, регрессиям и [приёмке фазы B](phase-b-acceptance.md). Число 12 в аудите относится к запускам. Один запуск может содержать несколько отказов. В частности, `20261110-140428` содержит оба отказа `SourceQualityCatalog`. Ниже указаны причины и привязки к регрессиям.

| Случай из аудита | Как воспроизведён и что защищено |
|---|---|
| `SourceDeliveryStandPreparation`, новый вызов `Write-RunStepMarker` | `FunctionClosureImport` добавляет вызываемую функцию в названном владельце. Фикстура её находит, соблюдает подмены и явно отказывает на отсутствующей подмене и неоднозначном корне. В фазе A добавление вызова в живую фикстуру также прошло 15/15. |
| `SourceQualityCatalog`, счётчики когорты и запас времени | В `20261110-140428` фактическая выборка выросла с 57 до 58. `fits the observed lifecycle cohort…` оценивает реальные пути и принимает законного потребителя. Фикстура с ростом за действующий жёсткий бюджет падает с оценкой и крупнейшими вкладами. |
| `SourceQualityCatalog`, точный набор для ROCTUP | В том же запуске `agent-1c-window-visibility` добавился к `roctup-port-lifecycle`. Регрессия `keeps mandatory Targeted owners…` добавляет потребителя в каталог фикстуры. Сохраняются оба обязательных теста, выбирается новый потребитель, путь `agent-1c.core.ps1` сохраняет исключение. Широкий тест lifecycle исключён из узкого маршрута. Для отдельно взятых путей действуют прежние бюджеты гейта. |
| `BootstrapUpdate`, новый action и дублирующийся список | `SourceQualityCatalog` проверяет валидатор реестров. Согласованный реестр проходит. Отсутствующий action и устаревшая запись дают `ACTION_REGISTRY_MISMATCH` с указанием всех рассогласованных мест. Проверка выполняется до Pester. |
| `ProductProjectContext`, точные счётчики | Классификатор тестируется по всему актуальному `ValidateSet`. Новый action сохраняет безопасный default с lock. Явные обязательные действия и полнота broker-операций проверяются в `ProductProjectContext` и `OnDemandMcp`. |
| `DevelopBrokerInputScope`, новый вызывающий и повтор устаревшего плана | Фикстура добавляет вызывающего. Гейт принимает изменение, а cold-cutover проекция отклоняется с именем вызывающего и требует полного выполнения. `SourceDeliveryRemoteMovement` проверяет отдельный повтор исходного отказа: перерегистрированный head даёт `DELIVERY_QUEUE_ADVANCED` с `-Replan` до гейта. |
| `ParserDocsBudgets`, переформулировка правила | Проверяется якорь `delivery-orphan-gate-wait`. Регрессия принимает два текста с тем же якорем и падает при его удалении. Блокировку при живом осиротевшем gate и последующее восстановление проверяет `SourceDeliveryOperationRecovery`. |
| `SourceDeliveryComponentPublication`, переформулировка диагностики | Прогон 40/40 для `SourceDeliveryComponentPublication` и `SourceDeliveryPublish` с временно переформулированным `Write-Verbose`. Файл восстановлен побайтно. Регрессия публикации проверяет выбранную Release capability и точный commit. Ошибка Release блокирует finalizer и push, следующий успешный запуск квалифицирует тот же commit. |
| `DeliveryGoInputScope`, изменение файла с проверенным SHA | При изменении живого `develop-configuration-rejection.ps1` тесты переиспользования по фикстурам проходят. Рабочая проверка входов отказывается от исключения, поэтому изменённый файл входит в доказательство. Подробности в приёмке фазы B. |
| `CompactRunnerWatchdog`, 9,19 с под нагрузкой | Тест фиксирует один резерв фазы, совпадение конечного дедлайна и отказ 8-секундной операции. Отдельная проверка ограничивает влияние задержанного чтения статуса по записанным часам runner. Исторический отказ виден в `Status -StatusDetail Full`. |
| `HostNativeTransport`, исторический нестабильный Develop | `20261110-092244`, tree `78a732a2`, виден в `unstableTests` при чтении журнала из worktree этой задачи. Фикстура `PesterIsolatedRerun` воспроизводит классификацию нестабильности и сохранение отказа гейта. Причина исходного сбоя Python и её устранение остаются неподтверждёнными. |
| Рассогласование Go-исходника и SHA lock | `OnDemandMcpLock` меняет вход сборки без перепиновки. Ранняя стадия выдаёт `ONDEMAND_LOCK_STALE`. Правки теста Go и README проходят, `Repin` обновляет связанные значения, проверка точной сборки проходит. |
| Рассогласование версий facade | `SourceQualityCatalog` воспроизводит `0.4.29` в compatibility и `0.4.28` в lock. Валидатор выдаёт `ONDEMAND_VERSION_MISMATCH` с обеими версиями до Pester. |

`Status -StatusDetail Full` уже показывает исторические `CompactRunnerWatchdog` и `HostNativeTransport` при чтении журнала из изменённого worktree. Поля в новых записях реального отказа, записанных опубликованным супервизором, проверяются отдельно от чтения старого журнала. Замороженные планы, закреплённые за прежним супервизором, используют его код.

Полная приёмка 5.1 остаётся открытой для исторического сбоя `HostNativeTransport`. Классификация этого случая подтверждена. Проверка реального HTTP и Linux watchdog продолжает требовать успешного результата.
