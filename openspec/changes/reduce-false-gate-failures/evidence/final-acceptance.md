Проверка 12 ноября 2026 года по [аудиту](failure-audit.md), записям в общем `.git/itl/runs`, регрессиям и [приёмке фазы B](phase-b-acceptance.md). Число 12 в аудите относится к запускам. Один запуск может содержать несколько отказов. В частности, `20261110-140428` содержит оба отказа `SourceQualityCatalog`. Ниже указаны причины и привязки к регрессиям.

## HostNativeTransport

В записи Develop `20261110-092244-288-develop-830e343410d64f21937415292c07b348.json`
сохранена первая строка отказа `Expected 0, because ...................F...`.
В `768508be` порядок `unittest` для 23 тестов ставит на позицию 20
`EndpointIdentity.test_slow_healthy_tool_uses_its_own_budget_through_the_real_child_transport`.
Отчёт упавшего worker с traceback отсутствует. Сохранённый JUnit того же дерева
относится к последующему успешному запуску. Исходники владельца в `768508be` и
`62aa01bb` совпадают.

На Windows с Python 3.13.13 до изменения прошли 24 запуска этого теста в отдельных
процессах, 16 параллельных прогонов всего Python-набора и 48 повторов теста с восемью
процессами на одном логическом CPU без фоновой нагрузки. При добавлении фоновой
нагрузки исходный тест воспроизвёл отказ. Диагностика показала превышение лимита
`initialize` в 1 с на внутреннем либо внешнем endpoint. В части прогонов
истекал общий дедлайн внутреннего дочернего процесса.

Подтверждён лишний расход времени в HTTP-транспорте. Стандартный
`HTTPSHandler` создавал TLS-контекст при каждой сборке opener, в том числе для
HTTP loopback. Двадцать созданий транспорта заняли 244 мс и вызвали двадцать
инициализаций TLS с медианой 11,6 мс. После изменения двадцать созданий заняли
3,9 мс, вызовов инициализации TLS было ноль. Контекст создаётся при первом
HTTPS-запросе. Регрессия проверяет реальный HTTP с запрещённой инициализацией
TLS, а отдельная проверка подтверждает обязательную проверку сертификата и
имени узла для HTTPS. Исходный тест по-прежнему выполняет HTTP через настоящий
дочерний Python с прежними дедлайнами идентификации 1 с и health 3 с.

| Нагрузка на одном логическом CPU | До изменения | После изменения |
|---|---:|---:|
| Восемь проверок параллельно и восемь фоновых процессов, одинаковые последовательные прогоны | 21 отказ из 24 | 12 отказов из 24 |
| Восемь проверок параллельно и четыре фоновых процесса, версии чередуются в одном прогоне | 1 отказ из 16 | 0 отказов из 16 |

После изменения свежий Pester-прогон `HostNativeTransport` прошёл 4/4, включая
весь Python-набор endpoint identity и Linux watchdog. Локальные журналы и
команды сравнения сохранены в `build/agent-artifacts/host-native-transport-5-1`. Тайм-ауты на прежних дедлайнах
при сильной перегрузке всё ещё воспроизводятся. Точный механизм отказа 10 ноября
по сохранившемуся журналу установить нельзя. Пункт 5.1 остаётся открытым.
