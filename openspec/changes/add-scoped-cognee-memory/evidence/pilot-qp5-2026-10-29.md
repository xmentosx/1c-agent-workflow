## Исходный отказ N1 и ограниченный ремонт

Первый настоящий stdio memory_status остановился до любой записи. Подтверждены
две причины, Cognee не дорабатывается:

1. Корректный owner applied record имеет 271093 bytes. Общий reader memory JSON
   допускает 262144. Отдельный typed reader applied envelope допускает до 4 MiB;
   ordinary memory records остаются ограничены 256 KiB. Он используется currentness,
   local status и context sync. Файл, его proof/baseline, hashes и правила не сокращаются.
2. Native client может наследовать PS7 module path. В таком stdio запуске проверка
   установленного policy не находила Get-FileHash. MCP entrypoint явно загружает
   Microsoft.PowerShell.Utility из собственного PSHOME, сохраняя проверку policy.

Два существующих It расширены исходными условиями, число случаев не увеличено:
большой compatibility envelope при прежнем bounded output и native stdio с
реальным inherited PSModulePath, теми же 3 RPC, Unicode path, child 10s / outer 20s.
Оба отказа воспроизведены до исправления; focused green — 2/0. Applied bytes
после чтения неизменны, общий memory limit продолжает отвергать oversized JSON.
Tool schemas и always-on инструкции не выросли; большой envelope не выдаётся агенту.

Read-only source-code diagnostic на настоящем binding прошёл за 3.543s:
binding current, task/workspace/workplace/project/organization destinations видны.
Это не установленный native proof и не benchmark; продуктовые writes требуют
ранее подтверждённого canonical home и не разблокируются ремонтом reader.
