## Результаты реализации (2026-11-10)

- **Пробы 1.3 и 1.5** — `docs/hidden-testclient-probe.md`. `/DisableSplash` не убирает окно
  «Загрузка конфигурационной информации...» клиента тестирования (8.3.27 и 8.5); у
  TestManager и `/Execute` такого окна нет. Скрытые диалоги работают с протоколом
  тестирования; положительный результат, реализация продолжена.
- **Отклонение от требования «заставка клиента не видна»**: помощник скрывает окно
  загрузки сразу по событию показа, но платформа применяет скрытие, только когда поток
  загрузки обрабатывает сообщения. Окно видно 1–2,3 с (без помощника около 1,7 с).
  Быстрее снаружи скрыть нельзя; нужно решение пользователя: принять ограничение или
  искать другой способ.
- **Живые проверки на этой машине** (пробная база, 8.3.27, `scratchpad`): диалог и
  предупреждение скрытого клиента скрыты за 46–100 мс с изображением в журнале;
  передний план, взятый скрытым окном, возвращается; `capture-show` даёт полный снимок
  без смены переднего плана; аренда `plain`, продление `kept`, конец через 2 с с
  возвратом фокуса и окном завершения. Окно согласия: отсчёт 3 с → аренда; та же
  область без окна (190–200 мс); «Отмена» → `user-cancel`, следующий запрос области
  сразу `scope-declined`; «Пауза» освобождает `Local\ITL-UiLease`, «Сейчас» продолжает.
  При открытом системном диалоге «Безопасность Windows» активация не удаётся:
  `ITL_WINDOW_ACTIVATION_FAILED`, ввода нет, фокус возвращён.
- **Найдено и исправлено живыми проверками**: глобальный хук показа и полный снимок
  процессов каждые 2 с давали 1,2 % ядра в простое (хук теперь по PID клиентов, полный
  снимок только первые 60 с после запуска или `adopt`); закрытое окно пользователя
  оставляло скрытого клиента на переднем плане (запасной выбор по Z-порядку);
  `ensure --hung` мог сообщить готовность по старому `helper.json`; кнопки системного
  стиля не нажимались в неактивируемом окне; переменная модуля формы
  `ITLИтогУправления` без `&НаКлиенте` ломала `GetStepsCache` сборки Single
  («Переменная не определена»), а `ТекущаяУниверсальнаяДата` в сроке запроса не
  работала в тонком клиенте; оба случая теперь проверяют статические тесты патча.
- **Не реализовано в этом изменении**: Pester машины состояний с фиктивным API окон
  (2.3, 2.5) — машина состояний проверена только живыми прогонами; панель «Жду паузы в
  вашем вводе» и предел удержания 60 с между двумя группами не проверялись; явный
  пропуск живого теста окна согласия в неинтерактивном прогоне отсутствует; явное
  `lease-end` по окончании сценария раннера не отправляется (аренда кончается через 2 с,
  смена области сбрасывает согласие); итог аренды в ответе vanessa-ui добавляется
  только к успешным ответам после аренды.
- **Нагрузка (2.6)**: три параллельные группы, 10 минут простоя после первой минуты:
  0,052–0,057 % одного ядра на помощник, рабочий набор 15,3 МБ (пик 29,4 МБ при старте),
  запуск `ensure` 0,28–0,30 с, ответ `status` 36–71 мс; после завершения корня все
  помощники вышли сами. Полный снимок процессов стоит около 15 мс (496 процессов),
  поэтому в простое он раз в 60 с, а раз в 2 с — только проверка живости известных процессов.
