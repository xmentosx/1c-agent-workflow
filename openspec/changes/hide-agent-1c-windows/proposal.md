# Proposal

## Why

Окна 1С, которые запускает workflow, выходят на экран и забирают фокус, пока
пользователь работает в других программах. Нажатия пользователя уходят в 1С,
иногда в окно, которого он не видит. Замер 2026-11-06
(`docs/testclient-focus-plan.md`): 21 выход окон 1С на передний план за один
Release E2E, из них 11 — запуск TestManager и TestClient. С 2026-11-06 клиент
тестирования запускается видимым (коммит `5b432565`), потому что VanessaExt не
видит скрытое окно.

Проба 2026-11-09 (`docs/hidden-testclient-probe.md`) показала: клиент можно
держать скрытым и показывать только для ввода ОС. Протокол тестирования со
скрытым окном работает полностью. Клавиатура и мышь VanessaExt работают в
показанном на время окне. Фокус возвращается пользователю. Но без проверки
активного окна ввод уходит в окно пользователя, а диалоги скрытого клиента
появляются видимыми.

Пользователь не должен терять управление внезапно. Перед тем как отобрать
клавиатуру и мышь, агент предупреждает и даёт отложить или отказать.

## What Changes

- **BREAKING (поведение по умолчанию)**: агентские процессы 1С запускаются без
  видимых главных окон и с `/DisableSplash`:
  - клиент тестирования раннера Vanessa и vanessa-ui MCP;
  - менеджер тестирования раннера;
  - процесс ROCTUP MCP.

  Заставка клиента тестирования не видна. Заставка менеджера и ROCTUP
  допускается, если платформа не убирает её по `/DisableSplash`; фокус после
  их старта возвращается пользователю. Режим `visible` возвращает прежнее
  поведение. Переключение действует со следующего запуска клиента, без отката
  ревизий.
- Управление у пользователя забирается только для ввода ОС (клавиатура и мышь
  через VanessaExt), арендой на серию соседних шагов. Снимок и список окон не
  забирают управление: окно показывается под окнами пользователя без
  активации и снимается только как окно процесса.
- Перед первой арендой в сценарии Vanessa или вызове vanessa-ui —
  полноэкранное окно согласия «Агент хочет получить доступ к интерфейсу»
  поверх всех окон, с обратным отсчётом (10 с по умолчанию) и кнопками
  «Сейчас», «Пауза», «Отмена», без кнопки по умолчанию. Согласие и «Отмена»
  действуют до конца сценария или вызова. На паузе окно сворачивается в
  маленькую панель поверх всех окон с теми же кнопками. Если пользователь
  продолжает печатать, аренда ждёт паузы в его вводе. После аренды — короткое
  окно «Операция завершена, можно пользоваться»: не забирает фокус,
  закрывается через 2–3 с или по нажатию. Отсчёт настраивается, 0 отключает
  окно для безлюдных стендов.
- Новый помощник окон клиентов тестирования:
  - маленький исполняемый файл, собирается на машине из исходника workflow;
  - работает на событиях Windows, в простое только сверка раз в 2 с;
  - прячет окна и диалоги скрытых клиентов, ведёт окно согласия, очередь и
    аренду, пишет журнал скрытых окон.

  Помощник одноразовый: его можно убить в любой момент, следующий запрос
  перезапускает его сам. Несколько экземпляров работают параллельно (проекты,
  пользователи терминального сервера) и не мешают друг другу. Готовность
  помощника проверяется до запуска клиента: если он недоступен (сборка,
  антивирус, AppLocker, длина пути), клиент запускается видимым с
  предупреждением, а прогон продолжается.
- Ввод ОС идёт только при подтверждённой активации окна клиента. Иначе шаг
  падает с явной ошибкой, ввод в чужое окно невозможен.
- Новая ревизия ITL-патча Vanessa:
  - скрытый запуск TestClient;
  - запросы к помощнику, дескриптор окна от помощника;
  - аренда для ввода ОС, снимки без активации;
  - учёт времени, когда управление было у агента.

## Capabilities

### New Capabilities

- `agent-1c-window-visibility`: невидимые окна агентских процессов 1С, аренда
  управления с согласием пользователя, защищённый ввод ОС, снимки без
  активации, одноразовый помощник и режим `visible`.

### Modified Capabilities

Нет: в репозитории нет опубликованных main specs.

## Impact

- Путь запуска (`Start-EnterpriseBackground`, `agent-1c.core.ps1`;
  `Start-OneCProcessBackground`, `agent-1c.sessions.ps1`;
  `Start-NativeProcessBackground`) — `/DisableSplash`, скрытие, запоминание
  окна пользователя, проверка готовности помощника; функция возврата фокуса
  после старта.
- `agent-1c.vanessa.ps1` (раннер, монитор живости, `Add-VanessaAgentLaunchParams`,
  диагностика отказа, итог времени аренды), `agent-1c.ondemand-mcp.ps1`
  (TestClient vanessa-ui), `agent-1c.roctup-mcp.ps1` (процесс ROCTUP,
  `Wait-RoctupMcpPort`).
- Новый исходник помощника (C#, .NET Framework 4.x, есть в Windows 10+) и его
  локальная сборка в кеш инструментов ITL пользователя. Новых выпускаемых
  бинарников нет.
- `third-party/vanessa-automation/`: новая ревизия `1.2.043.42-itl-rN` после
  r12 из очереди; пины в `templates/dependency-lock.json` и
  `assets/ondemand-mcp/compatibility.json`; пара EPF и CFE VAExtension.
- Настройки и документация (`MODES-AND-SETTINGS.ru.md`), правило авторинга
  Vanessa.
- Тесты Pester, Release E2E `vanessa-ui`, сценарии Vanessa с вводом ОС.
- Не меняются: Designer, служебные `/Execute` через `Invoke-Enterprise`, ручной
  запуск Vanessa вне ITL.
