# Acceptance and Evidence Plan

## Исходная точка (2026-11-14)

[Исходный срез](evidence/baseline-2026-11-14.md): task — 113 из 116 `remember`;
медиана длины реальной заметки — 706 символов; одна заметка — в 74% ответов
`recall`; медиана `recall` — 8 с; ошибок `recall` — 13,6%. Эти числа — база для
сравнения, а не доказательство приёмки.

## Уровни доказательств

1. **Source.** Pester в `tests/pester/ScopedCogneeMemory.Tests.ps1` на HTTP-фикстурах:
   - отказ `MEMORY_NOTE_TOO_LONG` с сохранённым pending и успешный повтор с тем же
     `note_id`; чтение старой длинной заметки;
   - маршрутизация по всем значениям `routeReason`; обновление и повтор остаются в
     исходном датасете;
   - destinations без строк workspace и product, со списком областей у проекта;
     явный workspace- и product-label принимаются;
   - порог внутри групп: нерелевантная лучшая заметка группы не выдаётся,
     чередование сохраняется, пустой ответ имеет `coverage=bounded`;
   - `truncated` вместо `partial` при достижении `top_k`; `partial` при сбое группы;
   - строка `/itl-check` с заголовками цикла, пределом 8 и «ещё N», без сети и при
     выключенной памяти.

   Бюджеты ядра и описаний инструментов — `ParserDocsBudgets.Tests.ps1` с
   измеренной разницей.
2. **Квалификация Cognee.** Наличие оценки сходства в `/api/v1/recall` и калибровка
   порога на 72 реальных запросах только на чтение — evidence задач 1.1–1.2.
3. **Форк.** Verify и Full форка на новом релизе; совместимость ai-rules в Targeted.
4. **Canary.** Одна копия PM5 после `update-workflow`, фактические вызовы клиента,
   по пунктам задачи 6.5.
5. **Пилот.** Первые ~15 сессий с изменениями BSL в копиях PM5 после обновления.

## Пороги пилота

Считаются по журналу `usage` и событиям `McpToolCall` в сессиях Codex. Без
блокирующих проверок; при недоборе — правка формулировок и повтор пилота.

| Показатель | Исходно | Порог |
|---|---|---|
| Доля `remember` в task | 97% | ≤ 30% |
| Новые заметки в project, product или organization | 2 | ≥ 3 |
| Медиана длины `data` новых заметок | 706 | ≤ 500 |
| Доля ответов `recall` с одной и той же заметкой | 74% | ≤ 25% |
| Медиана `recall` на сессию | — | ≤ 3 |
| Доля ошибок `recall` | 13,6% | не выше исходной |

## Что остаётся непроверенным

- Качество маршрутизации в клиентских проектах: в пилоте PM5 только проект
  разработки продукта.
- Поведение других клиентов (Cursor, Kilo, Claude) — только по схеме и бюджету,
  без пилота.
