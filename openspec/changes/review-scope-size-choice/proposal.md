# Proposal

## Why

С правилами r52 отдельное ревью (`get-review-scope -ReviewPurpose review`) охватывает всю работу ветки, а ревьюер обязан сам повторить проверки гейтов 1–3. На PM5 `itldev/branch4` это 76 BSL-модулей и около 2,7 МБ текста изменений. Ревью не может ни прочитать такой объём в одном контексте, ни передать модули в MCP-валидаторы, поэтому почти все проверки уходят в «unverified»: см. отчёт `D:\Git\PM5 КОРП - Codex - 1-branch4\reports\mcp-validation-worktree-gap-2026-11-06.md`. Пользователь хочет при большом объёме выбирать, что ревьюировать, а исправления, нужные при любом объёме, сделать в любом случае.

## What Changes

- `get-review-scope` для отдельного ревью оценивает размер объёма. Мера — объём текста изменений BSL. При нормальном объёме поведение прежнее. При большом объёме помощник предлагает пользователю три варианта:
  - только незакоммиченные изменения;
  - изменения начиная с выбранного коммита ветки, из списка с описанием каждого коммита;
  - вся работа ветки в режиме большого объёма.
- В отчёт `get-review-scope` при любом объёме добавляется состояние последнего `/itl-check` относительно текущего кода ветки: пройдена на текущем коде, устарела, не пройдена или не выполнялась.
- Правила ревью признают пройденный на текущем коде `/itl-check` доказательством гейта 1: его записывает пакет, и это не отчёт автора. Если такого результата нет, ревью не запускает проверку само, а рекомендует `/itl-check` в чате разработки.
- При большом объёме гейты 2–3 запускаются текстом по изменённым процедурам, выбранным по риску. Остальное помечается как «не проверено автоматически».
- Правила ITL сообщают, что на хостах ITL проверка файла по пути (`files`, `syntaxcheck_file`) недоступна и нужно передавать текст.

Самопроверка (`-ReviewPurpose self`) вопроса не задаёт; её поведение не меняется.

## Capabilities

### New Capabilities

- `review-scope-size`: оценка размера объёма отдельного ревью, выбор диапазона, сведения о свежести `/itl-check` и правила доказательства гейтов при большом объёме.

### Modified Capabilities

Нет опубликованных main specs. Контракт `get-review-scope` сейчас описан в `.agents/skills/1c-workflow/references/verification-result.md#review-scope`; это изменение его расширяет.

## Impact

- ITL: `agent-1c.review-scope.ps1` (размер, диапазон, список коммитов, свежесть), разбор параметров в `agent-1c.ps1` и `run-itl-command.ps1`, `references/verification-result.md#review-scope`, `templates/ai-rules-overlay/AGENTS.md`, `tests/pester/ReviewScope.Tests.ps1`.
- Controlled fork `ai_rules_1c`: `content/rules/review-criteria.md` (доказательство гейта 1 по проверке проекта, гейты 2–3 при большом объёме). Нужен новый выпуск r53 и перенос пина в ITL (`sections.json`, `dependency-lock.json`, `templates/project.json`, `scoped-memory-policy.json`, `DependencyLocks.Tests.ps1`, `docs/ai-rules-fork-upgrades.md`).
- Хосты MCP не перенастраиваются.

## Evidence

Подсчёт по 19 веткам `itldev/*` в двух репозиториях PM5. База — записанная база ветки, у пяти веток приблизительно `merge-base`. Скрипт и данные лежат в scratchpad сессии.

| Ветки | Изменено строк BSL | Текст изменений BSL |
|---|---|---|
| большинство | до ~1 300 | до ~90 КБ |
| 2-branch1 | ~6 100 | 526 КБ |
| 1-branch8 | ~10 000 | 850 КБ |
| 1-branch10 | ~27 500 | 2,7 МБ |
| 1-branch4 | ~40 700 | 2,7 МБ |

Между 90 и 526 КБ веток нет. Почти в каждой ветке, где менялся BSL, затронут модуль больше 300 КБ; максимум 5,7 МБ и 76 тыс. строк. Значит, проверить синтаксис целого модуля текстом в PM5 нельзя почти при любом объёме.

В `1-branch4` 75 из 76 модулей попали в служебный коммит `chore: checkpoint before branch refresh` от 28.10. После последнего обновления из master в ветке только 4 небольших исправления. Список «N последних коммитов» без описания был бы бесполезен.

Серверы `syntax` и `codechecker` в `vibecoding1c-mcp-host` глобальные. Проектных томов и `ONEC_AI_WORKSPACE_ROOTS` у них нет: `Get-HostDefaultEnvEntries`, `Get-HostDefaultVolumeEntries`. Поэтому отказ на любой путь ожидаем.
