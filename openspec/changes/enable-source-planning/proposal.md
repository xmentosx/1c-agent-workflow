## Why

При разработке `1c-agent-workflow` агент может начать реализацию с неверным пониманием задачи, выбрать избыточный механизм и затем наращивать исправления. По наблюдению пользователя, даже проверенные перед публикацией обновления приносят проблемы, блокирующие дальнейшую разработку в установленных проектах. Нужен способ согласовать достаточное решение и доказательства пользовательского результата до реализации; само наличие документов не доказывает снижение числа регрессий.

## What Changes

- Подключить к разработке исходного пакета `grill-me`, `grill-with-docs` и стандартный цикл OpenSpec. Первый поддерживаемый клиент — Codex.
- Агент сначала исследует доступные факты и предлагает grill и/или OpenSpec, если остаётся существенная неопределённость. Пользователь выбирает; обязательного формального цикла для всех изменений нет.
- В выбранной постановке связать проблему и сценарий пользователя, границы, простое достаточное решение и альтернативу, стоимость сопровождения, критерии приёмки и ограничения доказательств.
- Использовать этот change как первый пилот, включая проверку из нового контекста Codex и разбор одного известного сбоя обновления.

## Capabilities

### New Capabilities

- `source-planning`: добровольно выбираемые discovery и OpenSpec для разработки исходного workflow с передачей договорённостей и проверяемой приёмкой.

### Modified Capabilities

Нет существующих OpenSpec capabilities в исходном репозитории. Контракты установленного workflow и source delivery не изменяются.

## Impact

Область изменения: исходный репозиторий, навыки разработчика для Codex, краткая маршрутизация в корневом `AGENTS.md`, профиль OpenSpec и документация по постановкам. Общие навыки grill сохраняют своего владельца в controlled fork; исходный пакет получает воспроизводимую копию зависимости, без самостоятельного изменения её поведения.

За границами: включение этих файлов в bootstrap/update-workflow проектов, изменение runtime и gates, обязательный grill/OpenSpec, клиенты кроме Codex, публикация, создание новой системы управления состоянием задач. Выявленные пробелы исполнимой приёмки оформляются отдельными доработками.

## Agreed discovery handoff

Пользователь подтвердил решения Q1–Q6 в текущем чате:

- Приоритет — неверное понимание, избыточная сложность и цепочки исправлений, приводящие к проблемам после обновления.
- Агент предлагает инструменты; пользователь выбирает. Простой понятный баг сохраняет прямой путь.
- Пилот ограничен Codex.
- Триггеры предложения: разные трактовки поведения; недоказанная причина исправляемой проблемы; необоснованные новые состояния/исключения/восстановление; отсутствие конкретного сценария приёмки.
- До вопросов о намерениях агент сам устанавливает доступные факты. Рутинные инженерные детали решаются по действующим контрактам.
- Достаточная постановка содержит пять элементов из What Changes, масштабированных под задачу. Простота оценивается по суммарной стоимости эксплуатации и сопровождения, а не по числу изменённых строк.
- Пилот связывает постановку с приёмкой и разбирает один прошлый сбой; найденные изменения gates не включаются автоматически.

## Context Sources

- `AGENTS.md`: исходный репозиторий отличается от установленного проекта; неизменны ownership, изоляция работ, архитектурные ограничения, commit/RegisterChange и отдельная публикация.
- `docs/package-architecture.md`, Architecture scope and compatibility policy: один владелец инварианта, достаточная архитектура, существующий checkpoint при расширении ответственности.
- `docs/local-quality-gate.md`, Implementation and registration batching: один законченный контракт, регистрация сама запускает Targeted; создание постановки не является завершением реализации.
- `templates/dependency-lock.json`: grill исследован в controlled fork `itl-main-410951e7-r36`, commit `451c5a52e5b614c67406445d4af4b636da043aec`, `content/skills/{grill-me,grill-with-docs,grilling,domain-modeling}`. Generic interview и документация отделены от реализации.
- Пакет fork `content/openspec-bundle/codex/.codex/skills`: содержит 1С preflight, ссылки на 1С rules и `/itl-check`; прямой перенос не соответствует исходному репозиторию.
- Локальный OpenSpec CLI `1.4.1`: стандартная схема `spec-driven`, `new change`, `status`, `instructions`, `validate`; CLI уже доступен, установка не выполнялась.
- [OpenAI: Build skills](https://learn.chatgpt.com/docs/build-skills), прочитано 2026-09-26: repository skills в `.agents/skills`, явный вызов и настраиваемое неявное включение. Наличие файлов не заменяет проверку их обнаружения новым контекстом Codex.
- Ретроспективный случай и конкретные code/test anchors приведены в `test-plan.md`; это анализ покрытия, а не новый live-прогон обновления.
