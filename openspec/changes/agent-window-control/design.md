# Design

## Context

Мотивация — `proposal.md`, требования — `specs/agent-1c-window-visibility/spec.md`.
Основа — `hide-agent-1c-windows`:

- помощник окон держит группу процессов (корни и усыновлённые с потомками);
- помощник скрывает окна клиентов тестирования по событию показа;
- файловый канал протокола v1 поддерживает `lease`, `lease-end`, `capture-show`,
  `capture-end`, `adopt` и `status`;
- `Get-EnvValue` берёт переменную процесса раньше `.dev.env`;
- клиент тестирования vanessa-ui запускает сама Vanessa (патч r13: `WScript.Shell.Run(..., 0)`).

Ссылка `e1cib/app/Обработка.X` открывает отдельное окно. Поэтому помощник
успевает скрыть форму расширения только после её показа.

## Goals / Non-Goals

**Goals:**

- Ноль окон верхнего уровня для служебных форм расширения.
- Ноль видимых консолей при выпуске.
- Режим окон на один запуск.
- Показ и скрытие окон своей группы без потери фокуса пользователем.

**Non-Goals:**

- Скрытие окон менеджера тестирования и ROCTUP, их диалоги остаются сигналом
  ошибки.
- Показ окон чужих процессов.
- Ввод ОС без аренды.
- Изменение формы окна согласия.

## Decisions

### 1. Служебные формы — независимый режим окна в расширении (проба 2026-11-11)

Проба (`docs/hidden-testclient-probe.md`) повторила путь Vanessa на двух базах
со скрытым клиентом. Путь Vanessa: `ГлавноеОкно.ВыполнитьКоманду("e1cib/app/...")`,
затем поиск тестируемой формы. Результаты:

- С исходным расширением каждая форма с `LockOwnerWindow` показала окно
  `V8TopLevelFrameSDIsec`.
- Уже независимая `ПолучениеДанныхИзБазы` не показала ничего.
- Без `LockOwnerWindow` у шести форм нет ни одного показа, и тестовый API
  находит все формы.

Поэтому r14 меняет только `Form.xml` шести обработок `lib/VAExtension`. Ссылки
Vanessa и её код не меняются. Формы ищут целевое окно по заголовку через
`ПолучитьОкна()`, а не через владельца, поэтому режим окна не влияет на их
логику.

Отвергнуто — вариант a, общая команда расширения с `ОткрытьФорму`: он требует
изменения кода Vanessa и самой команды, а проба показала, что достаточно режима
окна.

Отвергнуто: ускорять скрытие в помощнике. Платформа применяет скрытие, только
когда поток окна обрабатывает сообщения (вывод r13), поэтому вспышка неустранима
снаружи.

### 2. Консоли выпуска: сначала поймать, потом исправить у владельца

В `measure-foreground-changes.ps1` добавляется запись показа окон верхнего
уровня: `EVENT_OBJECT_SHOW` для классов `ConsoleWindowClass` и
`CASCADIA_HOSTING_WINDOW_CLASS` с фактами процесса — образ, командная строка,
родитель. Запись идёт на всё время одной `PublishDevelop`. Каждый найденный
запуск переводится на общий запуск без окна. Общий запуск —
`Invoke-ItlNativeProcessCapture` или `CREATE_NO_WINDOW` в
`source-delivery-process.ps1`. Регрессия добавляется статическая на найденный
класс запуска (AST-проверка уже есть как приём) или поведенческая на владельца.

Отвергнуто:

- Сторож, скрывающий консоли во время выпуска: маскирует причину и гоняется со
  временем показа.
- Исправление «на глаз» без записи: статический разбор не нашёл источника.

### 3. Режим на один запуск — переменная процесса с источником

У `agent-1c.ps1` появляется параметр `-WindowMode hidden|visible`. Он задаёт
переменную процесса `ITL_RUN_WINDOW_MODE`, которую наследуют потомки. Единый
владелец режима `Get-OneCWindowMode` читает её раньше `ONEC_WINDOW_MODE`.

`ONEC_WINDOW_MODE` нельзя переопределить в окружении процесса: workflow много
раз импортирует `.dev.env` с перезаписью. Итог прогона и `window-helper-status`
показывают `modeSource=run|project`.

Для vanessa-ui видимость сеанса даёт показ по запросу (решение 4):
`window-show -VanessaTestPort <порт>`. Он держит клиент видимым со всеми новыми
окнами до `window-hide`, конца сеанса или перезапуска помощника.

Отвергнуто:

- `windowMode` в `manage_test_client(connect)`. Скрытие клиента vanessa-ui
  решается при запуске бэкенда: параметр канала окон передаётся при старте
  Vanessa. Поэтому режим при подключении потребовал бы перезапуска бэкенда или
  изменения закреплённого контракта инструмента Vanessa.
- Отдельный инструмент MCP: постоянный контекст схемы ради редкого случая.
- Смена `.dev.env` агентом: меняет проект для всех.

### 4. Показ и скрытие — операции помощника и команды `agent-1c`

В протокол v1 добавляются операции `show {pid}` и `hide {pid}` для процессов
группы. `show` выполняет `SW_SHOWNA` главного окна и окон процесса и ставит
процессу состояние «показан по запросу», при котором хук показа не скрывает его
окна. `hide` снимает это состояние и скрывает окна. Состояние живёт в памяти
помощника: перезапуск помощника или конец группы возвращает скрытие, как в
требовании.

Для агента появляются действия `agent-1c.ps1 -Action window-show|window-hide` с
`-ProcessId` или `-Port`. Они находят группу по членству процесса среди групп
помощников проекта (операция `status`). Действия не требуют lifecycle-блокировки,
как и действия `window-helper-*`. Для MCP отдельной операции нет: агент
сеанса vanessa-ui вызывает ту же команду с портом клиента.

Помощник собирается из исходника для каждой версии workflow, а Vanessa новых
операций не вызывает. Поэтому версия протокола и capability канала остаются
прежними. Набор операций остаётся одним контрактом:
- `protocol.json`;
- помощник;
- PowerShell-клиент;
- существующая проверка, которая расширяется.

## Risks / Trade-offs

- [Другие формы расширения или будущие ревизии upstream вернут `LockOwnerWindow`] → статическая регрессия патча проверяет шесть форм и запрещает добавленный блокирующий режим окна; запись окон показывает любое новое окно клиента.
- [Модальная форма расширения во вкладке ведёт себя иначе для шагов] →
  сравнение результатов шагов r13 и r14 на тех же сценариях в Release-стадии
  Vanessa.
- [Источник консоли не проявится за одну публикацию] → запись остаётся
  инструментом и повторяется на следующей. Пункт закрывается только записью без
  консолей.
- [Показанный клиент остаётся видимым, если агент забыл скрыть его] → скрытие
  возвращается концом сеанса или прогона, а `window-helper-status` показывает
  процессы, показанные по запросу.

## Migration Plan

- r14 публикуется как обычная ревизия патча: пины и парный CFE; код Vanessa не меняется, меняется только CFE `VAExtension`.
- Ветки получают её обычным обновлением.
- Откат — режим `visible` или прежний пин r13. Новые параметры необязательны:
  без них поведение r13.
