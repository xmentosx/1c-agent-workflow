# Design

## Context

Мотивация и доказательства — в `proposal.md`. Текущее состояние:

- `Invoke-ItlImmutableFileAcquire` (`agent-1c.immutable-download.ps1`) — единственный общий владелец получения файла с известным SHA256. Он копирует локальный источник или скачивает HTTPS-URL через `Invoke-WebRequest`: до трёх попыток, паузы 1 и 2 с, повторяются только транспортные ошибки и 500/502/503/504. Затем файл через staging атомарно публикуется с проверкой SHA256. Библиотека автономна: её подключают и установленный helper, и source-скрипты, и `itl-remote-runner`, поэтому зависеть от `agent-1c.core.ps1` она не может.
- Кэш до сети уже есть у владельцев Vanessa EPF и UI MCP, ROCTUP, Python runtime и mcp-catalog: `%LOCALAPPDATA%\ITL\artifacts\<family>\<version>\<sha256>`. YAxUnit (`Install-YAxUnit`) всегда качает в `.agent-1c/tools/yaxunit`. `Install-ItlOnDemandMcp` держит свой корень в `LOCALAPPDATA` и вызывает `Invoke-WebRequest` без повторов и без staging.
- `Get-GitHubApiHeaders` в core уже задаёт приоритет `GITHUB_TOKEN` перед `GH_TOKEN`. Тест `GitHubDependencyFallback` закрепляет этот порядок и неразглашение токена.
- Fresh-E2E (`invoke-develop-e2e.ps1`) не переопределяет `ITL_ARTIFACT_CACHE_ROOT` и уже пользуется общим кэшем машины для Vanessa.

## Goals / Non-Goals

**Goals:**
- Сделать GitHub REST API основным маршрутом для точных GitHub release URL у единственного владельца загрузок, а web-URL — резервным.
- Не требовать ключей и не хранить их. Если токен есть в окружении, использовать его только для API.
- Поставить YAxUnit и on-demand MCP под общий кэш и общего владельца.

**Non-Goals:**
- Изменение формата lock, публикации собственных ассетов, гейтов и E2E-топологии.
- Внутреннее зеркало (GitLab). Его можно добавить позже как ещё один маршрут того же владельца.
- ROCTUP skills (`raw.githubusercontent.com`, contents API) и обнаружение версий: они не относятся к release assets и уже ходят через свой API-helper.
- Чтение `.dev.env` в загрузчике. Токен берётся только из окружения процесса.

## Decisions

### D1. API — основной маршрут, web-URL — резервный
Порядок для точного GitHub release URL: API, затем locked web-URL.

Альтернатива «сначала web, API — резервный» отклонена. В наблюдаемом сбое web-маршрут тратит до 11 с на ответ, а затем отдаёт 504 из кэша edge. Короткие повторы бесполезны, а длинные увеличивают время bootstrap на минуты.

### D2. Поиск ассета во время выполнения, без нового поля в lock
`GET https://api.github.com/repos/<owner>/<repo>/releases/tags/<tag>`. Owner, repo и тег берутся из того же URL, тег URL-декодируется и экранируется заново. Затем ассет ищется по точному имени (ordinal), и используется его поле `url`. Холодная загрузка стоит два запроса API.

Альтернатива — хранить `githubAssetId` в lock: экономит один запрос. Отклонена, потому что добавляет поле, которое должны поддерживать публикация собственных ассетов и каждый, кто обновляет сторонний пин. Кроме того, нужны правило совместимости для установленных lock и отдельный тест согласованности. Вариант остаётся совместимым расширением на случай, если лимит станет проблемой.

### D3. Перенаправление без учётных данных
Запрос к asset endpoint выполняется с `Accept: application/octet-stream` и без автоматического следования перенаправлению. Загрузчик читает `Location`, требует схему `https` и скачивает тело отдельным запросом без заголовка `Authorization`. Так токен не уходит на CDN, а подписанный URL хранилища не получает лишнюю авторизацию. Поведение `-MaximumRedirection 0` различается в Windows PowerShell 5.1 и PowerShell 7, поэтому оно закрепляется тестом на обеих средах.

### D4. Токен необязателен и берётся из окружения процесса
Сначала `GITHUB_TOKEN`, затем `GH_TOKEN` — тот же приоритет, что у `Get-GitHubApiHeaders`. Загрузчик повторяет этот приоритет локально, потому что не может зависеть от core. Тест сверяет оба места. Токен не печатается, а из сообщений ошибок вырезается. Без токена лимит — 60 запросов в час на внешний IP, с токеном — 5000.

### D5. Матрица перехода на резервный маршрут
- API 403 или 429 (лимит), 5xx, транспортная ошибка, 404 релиза или ассета, ответ без `url` или `Location` — одно предупреждение без секретов, затем web-маршрут с прежней политикой: 3 попытки, паузы 1 и 2 с.
- `digest` ассета не равен SHA256 из lock — `InvalidDataException` до скачивания, без перехода на web. Байты там те же, и итог был бы тем же отказом.
- Сам API-маршрут не повторяется: резервный маршрут и есть его повтор. Общее ожидание — не больше одной API-попытки плюс прежнего web-бюджета.
- Итоговая ошибка содержит оба маршрута и последние статусы. Ошибка web-маршрута сохраняет прежнюю классификацию: 404 — не транзиентная, она нужна проверке доступности в source-delivery.

### D6. Кэш до сети для YAxUnit и on-demand MCP
`Install-YAxUnit` получает файл в `Get-ItlSharedArtifactPath -Family yaxunit -Version <version> -Sha256 <sha> -AssetName <asset>` и затем через тот же владелец публикует локальную копию в прежний путь проекта. Если в проекте уже лежит файл с нужным SHA, он принимается как есть. `Install-ItlOnDemandMcp` заменяет прямой `Invoke-WebRequest` вызовом общего владельца, а корень установки и проверка SHA остаются прежними.

### D7. Вызывающие вне YAxUnit и on-demand MCP не меняются
Vanessa, ROCTUP, client MCP, stand-env, Pester shards, release-readiness и source-delivery вызывают общего владельца и получают маршрут D1 автоматически. В source-delivery при неудачной HEAD-проверке web-URL полная загрузка уже идёт через владельца, а с API-маршрутом она проходит. Отдельная правка проверки доступности не нужна.

### Архитектурный checkpoint
Не требуется, по `docs/package-architecture.md`:
- изменение остаётся внутри существующего владельца;
- не появляются машинное или workflow-состояние, блокировка, координатор, перехват операций, повышение прав или миграция установленного состояния;
- always-on контекст не растёт.

Общий кэш уже существует и используется тем же способом.

## Risks / Trade-offs

- [Лимит 60 запросов в час без токена делится на всех за одним NAT] → Кэш до сети убирает повторные загрузки. При исчерпании лимита загрузчик переходит на web-URL, а не падает. Токен в окружении поднимает лимит.
- [API GitHub тоже может деградировать] → Web-маршрут остаётся резервным, итоговая ошибка называет оба маршрута.
- [Разное поведение перенаправлений в PS 5.1 и PS 7] → Тесты на обеих средах, плюс live-проверка на этой машине.
- [Fresh-E2E реже проходит сетевую загрузку YAxUnit из-за кэша] → Так уже устроено для Vanessa. Сетевой путь закрепляют unit-тесты с моками и холодный live-прогон с пустым `ITL_ARTIFACT_CACHE_ROOT`.
- [Изменение имени или тега ассета на стороне GitHub] → Это 404 в API и переход на web-URL. Подлинность по-прежнему решает SHA256.

## Migration Plan

Миграция установленного состояния не нужна. После `update-workflow` первая загрузка YAxUnit заполняет общий кэш, а существующий файл проекта с тем же SHA принимается. Откат — возврат к предыдущей версии workflow: файлы семейства `yaxunit` в кэше остаются неиспользуемыми неизменяемыми артефактами, а прежний путь проекта продолжает работать.
