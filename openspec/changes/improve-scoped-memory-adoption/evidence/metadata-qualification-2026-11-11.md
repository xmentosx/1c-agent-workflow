# Квалификация Cognee: имя заметки как носитель оглавления

Дата: 2026-11-11. Сервер: рабочий `cognee-qwen-prod-20261028-v1`, обычная техническая
учётка из общего подключения. Проверка выполнена по разрешению пользователя в
одноразовых датасетах `itl_qualification_*`; все пять датасетов удалены, финальный
листинг не содержит ни одного (`cleanup-verify`).

Сырые ответы без секретов и адресов:

- [run1](metadata-qualification-2026-11-11-run1.json) — метаданные и имя после
  обновления;
- [run2](metadata-qualification-2026-11-11-run2.json) — пределы имени, порядок
  списка, одновременное создание датасета;
- [run3](metadata-qualification-2026-11-11-run3.json) — одинаковое имя файла при
  обновлении, повторное использование имени, листинг больше 100 заметок
  (задача 1.2).

Описание API получено чтением `/openapi.json` того же сервера.

## Вопрос

Можно ли построить оглавление `memory_status` одним листингом датасета, не читая
оригинал каждой заметки, и остаётся ли оно верным после обновления заметки.

## Результаты

| Проверка | Результат | Шаг |
|---|---|---|
| `labels` и `external_metadata` из `/remember` после `PATCH /update` | Остаются как при создании; изменить нельзя (`PATCH` принимает только `data` и `node_set`) | run1 `listing-after-v2`, `listing-after-v3` |
| Повторный `/remember` того же содержимого с новыми метаданными | Метаданные не меняются, дубля нет, 0,3 с | run1 `remember-identical-v3-with-new-metadata` |
| Поле `name` в листинге после `PATCH /update` | Равно имени нового файла без расширения, при каждом обновлении | run1 `listing-after-v2`, `listing-after-v3` |
| Кириллица и пробел в имени | Сохраняются без искажений | run1 `listing-after-v3`, run2 `order-after-update` |
| `data_id` после обновления | Не меняется (`status: incremental`) | run1 `update-v2-ascii-name`, `update-v3-cyrillic-name` |
| `updatedAt` после обновления | Обновляется | run1 `listing-after-v2` |
| Предел имени при создании | Файловая система сервера: имя вместе с `.txt` и служебным суффиксом — до 255 байт UTF-8. 204 байта ASCII и 200 байт кириллицы приняты; 255 байт ASCII и ~300 байт кириллицы — `500 File name too long` | run2 `add-ascii-200`, `add-ascii-251`, `add-cyrillic-100`, `add-cyrillic-150` |
| Предел имени при обновлении | 184 символа (~300 байт) приняты | run2 `update-long-cyrillic-name` |
| Точки внутри имени | Срезается только последнее расширение | run2 `add-dots-tilde` |
| Знаки `~ \| : % # ( ) [ ] { } & + = , ; ' ! @ "` | Сохраняются | run2 `add-punctuation`, `add-quote` |
| Пробелы по краям | Сохраняются | run2 `add-spaces-edges` |
| `/` и `\` в имени | Имя обрезается до последнего сегмента пути | run2 `add-slash`, `add-backslash` |
| Второй документ с тем же именем и другим содержимым | `409 Document already exists; use the update endpoint` с `data_id` существующего | run2 `add-duplicate-b` |
| Две заметки одного датасета обновлены с одним именем файла `memory.txt` | Оба обновления приняты, обе заметки называются `memory`, содержимое каждой своё | run3 `update-first-as-memory-txt`, `update-second-as-memory-txt`, `raw-after-same-name-updates` |
| Создание заметки с именем, которое раньше носила переименованная | Принято | run3 `add-with-freed-name` |
| Создание заметки с именем, которое сейчас носит другая | `409`, включая имя, полученное обновлением | run3 `add-with-name-in-use` |
| Порядок листинга | По `createdAt`, новые выше; не по `updatedAt` | run2 `listing-default-order` |
| Листинг 120 заметок | По умолчанию 100; `limit=1000` — все 120 за 0,49 с; вторая страница — 20 за 0,27 с; счётчик 0,27 с | run3 `volume-listing` |
| Страницы листинга | `limit` до 1000 (по умолчанию 100), `offset` работает; есть `/data/count` | run2 `listing-paging`, `count` |
| Повторный `POST /datasets` с тем же именем | Возвращает тот же датасет | run1 `create-dataset-again-same-name` |
| Два одновременных `POST /datasets` с новым именем | Один датасет, один ID | run2 `concurrent-create-same-name` |

Времена на этом сервере: листинг датасета 0,27–0,31 с; чтение оригинала 0,29 с;
`/remember` одного файла 30 с, двух файлов одним запросом 14 с; `PATCH /update`
13–15 с.

## Выводы для дизайна

1. Метаданные для оглавления непригодны: они замораживаются при создании.
2. Имя документа пригодно: оно уходит тем же запросом, что и содержимое, и
   заменяется при каждом обновлении. Оглавление строится листингом.
3. Создание заметки переводится с `raw_data` на отправку файлом, иначе имя задаёт
   сервер.
4. Имя должно быть уникальным в датасете (иначе `409`), не содержать `/` и `\` и
   укладываться в 200 байт UTF-8 с запасом до предела создания.
5. Сортировку по свежести выполняет адаптер по `updatedAt`: сервер упорядочивает
   по `createdAt`.
6. Сервер сам возвращает существующий датасет по имени, в том числе при
   одновременном создании.
7. Уникальность имени проверяется только при создании. Копии с предыдущей версией
   workflow, которые обновляют заметки с именем `memory.txt`, продолжают работать
   без отказов; их заметки получают имя старого формата и читаются через оригинал.
8. Листинг одной страницей до 1000 записей укладывается в полсекунды на 120
   заметках.

## Не проверено

- Листинг и его время на датасете в сотни и тысячи заметок: проверено 120.
- Поведение на другом образе Cognee: квалификация относится к профилю
  `cognee-qwen4096-v1` на 1.6.5.
