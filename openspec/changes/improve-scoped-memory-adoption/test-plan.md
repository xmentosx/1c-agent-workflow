## Уровни доказательств

1. **Source.** Pester в `tests/pester/ScopedCogneeMemory.Tests.ps1` на поведение из
   спек:
   - коды сбоя чтения локальной записи;
   - идентичность, дополнение привязки и переход, отказ первой записи после смены
     цикла или проекта;
   - workspace локального проекта, неизменный ключ `checkpoint`;
   - три статуса, имя документа, уникальность и предел имени, ID без датасета;
   - оглавление без чтения оригиналов, применимость области, потолок 2000 токенов;
   - `host`-ключ, поиск датасета перед созданием;
   - разбор pending, компактные destinations, журнал с идентификатором сессии и
     без текста запроса, информационная строка `/itl-check`.

   Бюджеты постоянных правил и описаний инструментов — в
   `ParserDocsBudgets.Tests.ps1`, с измеренной разницей. Тесты используют фикстуры
   HTTP, а не рабочий сервер. Фикстура повторяет квалифицированное поведение
   сервера: имя следует за обновлением, метаданные не меняются, `409` на повтор
   имени.
2. **Квалификация Cognee.** Выполнена 2026-11-11 на рабочем сервере в одноразовых
   датасетах, три прогона: [evidence](evidence/metadata-qualification-2026-11-11.md).
3. **Установленная копия (canary).** После `update-workflow` на одной копии PM5, до
   обновления остальных — пункты задачи 12.1. Фактические вызовы клиента, а не
   конфигурация.
4. **Пилот.** Первые ~15 сессий с изменениями BSL в копиях PM5 после установки.

## Пороги пилота

Изменение считается принятым, когда пилот показывает:

| Показатель | Порог | Источник |
|---|---|---|
| `memory_status` в начале сессии | не меньше 90% сессий | логи Codex |
| `recall` до первой правки BSL | не меньше 80% сессий | логи Codex |
| строка `Memory:` в итоговом ответе | не меньше 80% сессий | логи Codex |
| ошибки инструментов памяти | не больше 5% вызовов | журнал, сверка с логами Codex |
| исправления пользователя сохранены в том же ходе | выборочная проверка 5 сессий | логи Codex |

Логи Codex — основной источник: журнал не видит сессий без вызовов памяти, правок
BSL и текста ответа. Метод тот же, что для исходной точки. Журнал даёт долю ошибок,
вид записи при сбое чтения и идентификатор сессии для сверки.

Недобор порогов исправляется формулировками ядра и описаний инструментов и
повтором пилота, а не новыми блокирующими проверками. Результат —
`evidence/pilot-<дата>.md`.

## Что остаётся непроверенным

- Клиенты Cursor, Claude и Kilo в пилоте не участвуют. Ядро они получают из общего
  корня; их приёмка — по отдельному поручению.
- Терминальный сервер с несколькими пользователями: `host` проверяется на одной
  машине с двумя профилями Windows, если такой стенд будет доступен. Иначе это
  остаётся открытым и записывается в evidence.
- Поведение имён документов на другом образе Cognee.
- Причина двух `MEMORY_RECORD_INVALID` из исходной точки: по логам не
  восстанавливается, локальные записи сегодня исправны.
