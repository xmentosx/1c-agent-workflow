# Spec Delta

## Purpose

Связать бизнес-проект с фактическими источниками MCP и внешними объектами так, чтобы выбор области действительно соблюдался сервером, а поиск и создание задач использовали явные проектные настройки.

## ADDED Requirements

### Requirement: Независимые роли и приоритет настроек

Система SHALL разрешать `code`, `graph`, `productDocs` независимо в состояниях `inherit`, `own`, `disabled`, с приоритетом локальное переопределение → проект → продукт с необязательным выбранным профилем. `inherit` SHALL продолжать разрешение на следующем уровне; `own` SHALL задавать полный binding роли; `disabled` SHALL прекращать наследование. Остальные MCP SHALL сохраняться общими, включая Cognee при его отдельном qualified opt-in: `memoryHomeProductId` выбирает продуктовую область данных, SHALL NOT вводить проектное наследование endpoint или четвёртую роль. Отсутствие binding SHALL NOT неявно выбирать произвольный источник.

#### Scenario: Разные code и graph
- **WHEN** проект задаёт собственный code, наследует graph, а локально отключена документация
- **THEN** разрешаются три независимых результата; code `configId`/host не копируются в graph, документация не включается обновлением продукта

#### Scenario: Внешний проект без своего индекса
- **WHEN** выбран собственный code, но его binding ещё не заполнен
- **THEN** роль требует настройки; базовый код продукта не объявляется кодом проекта и доступен лишь как явно обозначенный дополнительный источник

### Requirement: Проверяемая техническая идентичность

Binding SHALL различать бизнес-ID, endpoint host/server/configuration, native namespace и наблюдаемую generation/revision. Готовность SHALL подтверждаться MCP handshake и безопасным функциональным чтением с ожидаемым контекстом; доступность URL или запись в registry недостаточны. Утверждение о версии исходников SHALL иметь соответствующее доказательство, а не только строку версии registry.

#### Scenario: Одинаковый внутренний ID
- **WHEN** два endpoints возвращают `code-20d3eae87f48`
- **THEN** они остаются разными источниками по полному binding; один внутренний ID не объединяет бизнес-проекты

#### Scenario: Неожиданный namespace
- **WHEN** endpoint доступен, но возвращает другой источник, чем выбранный
- **THEN** роль не объявляется готовой; показывается ожидаемый и фактический binding без подмены соседним endpoint

### Requirement: Соблюдение области документации

Выбранная роль `productDocs` SHALL обеспечивать одну и ту же серверную область для cache, semantic, live fallback и чтения страницы. Стабильные selectors SHALL валидироваться; неизвестный selector SHALL NOT расширять поиск до всех документов. При отсутствии серверного механизма область SHALL показываться неподтверждённой, а глобальный endpoint SHALL NOT молча заменять выбранный.

#### Scenario: Несуществующая книга
- **WHEN** поисковый запрос содержит несуществующий ID/selector книги
- **THEN** сервер возвращает понятную ошибку либо пустую область по документированному контракту и не возвращает чужие страницы через live fallback

#### Scenario: Чтение чужой страницы в выбранном источнике
- **WHEN** клиент выбранной области запрашивает page ID вне её состава
- **THEN** область соблюдается и при чтении; глобальная доступность страницы в BookStack не делает её частью выбранного источника

### Requirement: Связи с существующими СППР и Mantis

Проект SHALL поддерживать необязательную связь с одним проектом СППР и списком проектов Mantis внутри явно указанных установок систем. Каталог SHALL ссылаться на существующие native IDs и показывать доступные проверенные названия. Регистрация связи SHALL NOT создавать внешние проекты, расширять сбор индекса или изменять серверные права. Общие MCP SHALL позволять явное чтение известного объекта/обращения без заполненной проектной связи.

#### Scenario: Ещё не заполнена СППР
- **WHEN** локальный проект не имеет связи СППР, но разработчик указывает существующий объект явно
- **THEN** доступное серверу чтение разрешается, а отсутствие связи не блокирует локальную работу

#### Scenario: Ссылка на неиндексируемый проект
- **WHEN** запись ссылается на существующий проект СППР вне текущей области коллектора
- **THEN** система сообщает недоступность данных и необходимую отдельную настройку; каталог не запускает сбор автоматически

### Requirement: Поиск Mantis по нескольким проектам

Mantis SHALL поддерживать явный список project IDs как одну область поиска, сохраняя совместимость скалярного фильтра и прежнего поиска без фильтра по доступным проектам. Область SHALL применяться до ограничения кандидатов, во всех способах поиска и на всех страницах; ответ SHALL честно показывать ограничение полноты. Пустая область SHALL NOT означать поиск по всему Mantis.

#### Scenario: Ошибки и развитие
- **WHEN** область поиска содержит проекты 699 и 815
- **THEN** результаты относятся к объединению этих двух проектов, без третьих проектов; cursor продолжает ту же область

#### Scenario: Совпадение за пределами глобальных кандидатов
- **WHEN** релевантная задача выбранного проекта находится за первыми 10000 глобальными кандидатами
- **THEN** фильтрация до ограничения сохраняет её доступность; результат не объявляет пустоту проекта из-за чужих кандидатов

### Requirement: Маршрутизация создания и точные связи

Настройки SHALL различать область поиска Mantis и целевой проект по назначению задачи, например `bug`, `feature`, `improvement`. При отсутствии или неоднозначности маршрута создание SHALL требовать явный целевой проект и использовать существующий writer/idempotency contract. Связь объекта СППР с задачей SHALL подтверждаться точным полем/ссылкой, а сходство текста SHALL обозначаться только как рекомендация.

#### Scenario: Разные цели создания
- **WHEN** `bug` направлен в 699, а `feature` в 815
- **THEN** создание использует назначение задачи и правильный target; первая запись списка поиска не считается универсальным primary project

#### Scenario: Нет маршрута
- **WHEN** пользователь хочет создать задачу, но её назначение не сопоставлено проекту
- **THEN** требуется явный target для этой операции; другие действия workflow продолжают работать

#### Scenario: Точная ссылка СППР
- **WHEN** объект имеет `итлКодMantis=59095`, а семантический поиск также нашёл похожую другую задачу
- **THEN** только 59095 показывается фактической связью; другая задача помечается похожей
