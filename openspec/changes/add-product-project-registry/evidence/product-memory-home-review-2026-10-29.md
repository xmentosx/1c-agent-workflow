## Как не потерять различия редакций и конфигураций

1. Знание общей PM-области из ERP+PM записывается в КОРП соответствующего
   поколения с исходным origin. ERP-зависимость не исчезает: при ней факт
   ограничивается ERP+PM и нужными компонентами. В ПРОФ он не становится применимым.
2. У подчинённых планов, статус-отчёта и первичных документов сохраняются прежние
   ограничения. Например, заметка про один сводный план ограничивается
   ПРОФ/УНФ+PM; факт об автоматическом заполнении рисков — КОРП/ERP+PM.
   Соседство заметок в dataset КОРП не разрешает использовать их во всех редакциях.
3. Удалённые из ПРОФ функции исключаются по исходной карте `availableIn`.
   Пример: риск-менеджмент не выдаётся ПРОФ/УНФ+PM только потому, что найден в КОРП.
4. Особенность клиентского внедрения остаётся в project/task candidate, пока
   отдельно не подтверждена её общая продуктовая применимость. Инфраструктура
   и договорённости типовой разработки тоже остаются проектовой памятью.
5. Для чисто ERP/УНФ знания вне существующих PM-областей нет автоматически
   назначенного home: это project/task candidate до отдельной карты такой области.
   Области для 1С:ERP, 1С:УНФ, Renga, отдельных расширений и внешних проектов
   в этот кандидат не добавляются.

Выбор home памяти не меняет Code/Graph/productDocs MCP. ERP+PM5 сохраняет
собственную пару `erppm5-lts`; маршруты СППР/Mantis и источник индексов прежние.
Origin, версия источника и применимость факта продолжают храниться раздельно.
