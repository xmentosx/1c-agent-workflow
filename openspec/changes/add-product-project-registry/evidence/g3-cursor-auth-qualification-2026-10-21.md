## Продолжение после входа

1. Пользователь выполняет штатный **Log In** в оставленном тестовом Cursor, не Sign Up. Если браузер не открывается, использовать предлагаемый самим Cursor UI путь входа; не доставать login callback/token из private storage/API. Если подходящего аккаунта нет, blocker остаётся открытым без сокращения поддержки или нового обхода.
2. После ответа о завершении входа проверить **видимый** authenticated frontend и exact original PROF workspace. Новое окно/root/profile не подставлять молча. Если пользователь выбирает существующий авторизованный профиль, отдельно зафиксировать изменение области квалификации и сохранить прежний failed profile; credentials не копировать.
3. В обычном Agent UI проверить доступ к двум нужным project MCP через штатные controls; не выводить его из файла `.cursor/mcp.json` или worker connection. Выполнить один bounded canary: ровно Code `stats({})` и Graph `list_graph_projects({})`, без shell/write/reindex, затем проверить actual inputs/payloads и expected source. Подтверждать только конкретные read permissions; глобальный auto-run не включать.
4. Проверить native reload и fresh preservation, зафиксировать реальные usage counters/ошибки и закрыть owned Cursor обычным способом. До этого actual agent reads, signed-in reload и полный критерий остаются **unverified**.

Успешное продолжение OpenCode на отдельной 1.19.3 не заменяет Cursor acceptance. Native Cursor account, profile ID и Agent switches не становятся business product/project IDs, registry credentials или memory home/grants. Поля конфигурации/версии источника по-прежнему приходят из registry/applied context; новые Code/Graph patches, auth mapping, central account store или memory probe не требуются.
