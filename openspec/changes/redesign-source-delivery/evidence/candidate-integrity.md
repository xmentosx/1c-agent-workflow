# Qualified candidate integrity (C8)

The existing publication coordinator owns the new private integrity helper.
Before external finalization and again after it, the helper requires the exact
qualified commit, tree and clean working tree, including untracked files.
Git paths remain NUL-delimited through the shared path-list helper. Develop push
names the qualified commit explicitly instead of the current HEAD. Existing
component planning, compatibility promotion and installability validation still
precede final proof; the helper prevents callbacks from silently invalidating it.

Failure retains the original plan and queue, invalidates component finalization
and restores its qualified phase. The ordinary same-plan publication command
reconstructs the original candidate and reuses applicable qualification. A new
reset/replanning protocol is unnecessary for these callback mutations. Already
pushed recovery remains owned by the existing coordinator. Historical controller
rollback, changed frozen source and other proof failures remain C9/C11 work.

Two private native scenarios passed before extraction: a gate creates an extra
commit; a finalizer creates an untracked file. Neither mutated candidate reaches
the remote branch. After the callback is repaired, explicit trusted ResumePlan
publishes the same candidate and plan; Develop runs once. Finalization runs once
for the first scenario and twice for the second. Each scenario preserves the
original queue through failure and clears it only after successful publication.
The original task therefore passes through the new barrier. These injected gates
do not qualify actual 1C or component assets.
