# Приёмка поиска и записи Mantis MCP

Статус на 28.09.2026: **исходная реализация и локальные проверки; внешняя приёмка открыта**. Индекс/запись по умолчанию выключены. Реальные записи, изменение прав, развёртывание и платные запросы не выполнялись. Покрытие ниже различает fixtures, настоящие локальные зависимости и обязательную проверку на сервере; наличие сценария само по себе не означает его прохождения.

## Уже полученные доказательства

Read-only исследование подтвердило версию 2.28.1 и роль наблюдателя, структуру metadata, получение полного обращения/оригинальных файлов, две страницы REST по `updated_at` с закрытыми обращениями и отдельный каталог меток. Данные, объёмы и ссылки приведены в [design](design.md#context) и [ADR 5](../../../docs/adr/0005-mantis-modified-date-delta.md). Ошибка SOAP-фильтра 500 воспроизвелась дважды; её причина не установлена. Во время реализации новый адаптер отдельно проверен read-only в памяти существующего контейнера: 17 проектов, access level 10, 354 метки, SOAP definitions настраиваемого поля и фактические REST config keys. Файлы/образ контейнера не менялись, токен в вывод не попадал. Рабочий ключ приватности — `change_view_status_threshold`; учтено исключение reporter для приватных issue/note по upstream access_api.

Время локальных fixtures зависит от filesystem и не доказывает SLA Mantis.
Docker CLI обнаружен, но локальный Linux engine недоступен (pipe
`dockerDesktopLinuxEngine` отсутствует); Docker/службы не запускались. Поэтому
1.4 остаётся открытой в части Linux Python 3.12 образа. Проверки 6.3–6.4 также
открыты: реальные права/каждая write-ветка, конкурентный UI, private-note file,
сетевая передача actor, качество модели/стоимость, нагрузка и freshness ≤300 s.
Приёмка process-kill/rollback на целевом хосте не подменяется локальной имитацией
границ фиксации и повторным открытием SQLite/Zvec.

RegisterChange запускает единственный итоговый Targeted для нового диапазона;
его состояние и точный head читаются через source-delivery Status. Публикация
и live-приёмка не фиксируются checkbox локальной регистрации.

## Контуры и правила доказательства

- Unit/fixture: детерминированные ответы API, fake clock, равные timestamps, движение страниц, потеря соединения после серверного side effect, подсчёт отправок и расхода. Fixtures воспроизводят ограничения 2.28.1, а не подразумевают атомарный API.
- Integration: реальные SQLite + закреплённый Zvec и filesystem в временном owner-local состоянии; restart/kill на границах фиксации. Fake Mantis/OpenRouter позволяют доказать алгоритм без записей в production и затрат.
- API qualification: отдельно разрешённый тестовый MantisBT 2.28.1 с той же существенной конфигурацией; аккаунт/проекты/действия фиксируются. Правка production не служит тестовой фикстурой.
- Canary: только после разрешения этого этапа, на определённом проекте. Измерение полного объёма, стоимости и load не подменяется старыми пробами на 20/100 обращениях.

Для каждого сценария сохраняются версия кода/образа и dependencies, параметры контура, вход/наблюдаемый результат, время, применимые request counts и IDs без секретов. Source delivery, установка и live acceptance отмечаются отдельно. Failing case исправляется у владельца; воспроизводящие условия и assertions не ослабляются ради зелёного результата.

## Измерения canary

После разрешения зафиксировать размер базы/фрагментов/файлов, baseline latency существующих reads и ресурсы Mantis/MCP. Отдельно измерить первичный импорт и устойчивый режим дельты по нескольким проектам: запросы/байты на цикл, backlog, время изменения → текстовая выдача → семантическая выдача, стоимость и свободное место. Неизменяемые старые обращения не перечитываются каждым циклом.

Для обычных изменений в утверждённом наборе сценариев при исправных зависимостях каждое наблюдение должно укладываться в 300 секунд после завершения первичного импорта; представить распределение и худшее значение, а не только среднее. Сбои провайдера/бюджета и silent-change сценарии вынести отдельно со статусом, не включать их в ложную гарантию. Допустимую нагрузку и параметры canary согласовать по измеренному baseline; перед измерением не назначать произвольный лимит как уже подтверждённый SLA.

## Завершение

Apply завершён только при доказательствах применимых сценариев, документированной матрице реально включённых write-веток и проверенном recovery/rollback. Непроверенные контуры отмечаются явно и не закрываются checkbox. RegisterChange подтверждает локальный source gate; публикация и ввод в эксплуатацию требуют собственного разрешённого этапа и не следуют из этого файла автоматически.
