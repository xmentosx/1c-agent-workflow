## Согласованный первый пилот, 2026-10-28

Пользователь выбрал **первый пилот в проверенном контуре PM5 / Windows 11**.
Реестр сохраняет все восемь типовых продуктов; квалификация installed PM4,
других Windows/терминальных сессий и остальных частей R1–R5 остаётся
**UNVERIFIED**, а не PASS. Это явная выпускная оговорка пилота; заявленная
поддержка и runtime guards не сокращаются. Клиенты принимаются только в
ранее доказанных границах: Codex CLI/core/API не подменяет Desktop/model UI,
OpenCode остаётся SKIPPED. Принятый небольшой warm cost не переоткрывается.

Новый Develop закрывает выполненные upgrade/fresh маршруты в своём scope:
update/verification-export и install/branch/verification/stale-export/refresh/close.
Он не доказывает отдельные foreground/fork/platform/client случаи. Полный
остаток остаётся в [единой R1–R5 матрице](../openspec/changes/add-product-project-registry/g3-acceptance.md).
G3/G5/MO не переоткрываются; новых случаев или обязательных gates нет.

Следующая операция — прежний **QP5**: финальная сверка Tf и late changes,
общий адрес `http://dev-karimov-new.itland.local:18220/`, прежний qualified
Qwen profile/4096 и native mappings; применение только через existing
setup/reload owner к явно выбранному пилотному binding. Рабочий старт был
пустым; fixture/qualification записи не становятся рабочими данными.
Один normal writer target, явный off сохраняется; BGE, snapshots и путь
возврата остаются. При незавершённом admission память unavailable, каталог
и основной workflow продолжают работу. Секреты/UUID не переносятся в реестр.

Выбор границы пилота сам по себе не отмечает QP5 выполненным и не снимает
прежние отдельные запреты на cutover, новые Gate 6, рабочую миграцию и
публикацию в этом чате. Перед этими действиями требуется явный допуск к
конкретной операции. Массовое обновление рабочих проектов не входит в пилот.

## Как будет работать выпущенный workflow

### Новый локальный проект

1. Инициализация предлагает выбрать бизнес-проект из общего реестра. Один
   бизнес-проект могут использовать несколько локальных папок разработчиков.
2. Продукт, известные MCP, СППР/Mantis и различия проекта с типовым MCP-источником
   берутся из выбранной записи. Повторять вопросы по каждой настроенной связи не нужно.
3. Пользователь задаёт обязательные локальные параметры, например исходную базу.
   Дальше работает обычный bootstrap и настройка выбранного клиента.
4. Память включается по умолчанию, когда готовы привязка, квалифицированное общее
   подключение, mappings и активация/reload. Шесть областей определяются из контекста;
   отдельный Cognee на каждый проект и анкета из шести вопросов не нужны.
   Отсутствующая настройка памяти получает понятное продолжение; независимая работа
   workflow продолжается, требующая памяти операция не объявляется завершённой.
5. Если проекта нет, можно добавить запись. При наличии Git-прав она сохраняется
   штатно, иначе готовится запрос на добавление. Внешние проекты СППР/Mantis и
   сообщения другим людям автоматически не создаются.

### Обновление существующего локального проекта

1. Первое успешное интерактивное совместимое обновление непривязанной установки
   предлагает выбрать проект, создать запись или отложить. Это не переинициализация
   базы и не сброс веток.
2. Явное «позже» сохраняется для текущей локальной копии/пользователя и не вызывает
   повторный вопрос при каждом обновлении; выбор доступен через настройки.
   Отсутствие ответа или unattended-запуск не являются согласием и сохраняют legacy-режим.
3. Перед первой привязкой показываются изменения настроек. Свои MCP и выключенные
   связи сохраняются; конфликт разрешается как «оставить локальное / взять из реестра /
   отложить» через существующего владельца применения и восстановления.
4. У уже привязанного проекта повторный выбор не нужен. При обычных командах
   бесконфликтные унаследованные изменения реестра обновляются штатно; локальные
   overrides сохраняются. При недоступности реестра используется последний валидный
   применённый snapshot для независимой работы. Неразрешённый конфликт может
   остановить зависимую команду с продолжением, а не перезаписать настройки молча.
5. Явно выключенная память остаётся выключенной. Старые заметки автоматически
   не импортируются. Обновление пакета само по себе не разрешает массовую миграцию.

Это изложение существующих требований, не новый сценарий или новая приёмочная
матрица: [init/update](../openspec/changes/add-product-project-registry/specs/registry-project-configuration/spec.md),
[создание записи](../openspec/changes/add-product-project-registry/specs/product-project-registry/spec.md),
[default-on](../openspec/changes/add-scoped-cognee-memory/specs/memory-policy-and-budget/spec.md).
