# Соразмерная проверка результата перед отчётом о готовности

Основание — согласованный разбор Канбана branch4 и поручение от 25.10.2026.
Проверяется результат задачи; UI нужен там, где без его наблюдения остаётся
существенный риск. Новый гейт, реестр, обязательный документ или UI-тест на
каждую правку не вводятся. Установленные проекты и их базы не изменяются.

## Владелец и изменение контракта

Controlled fork продолжает r47 на прежнем upstream `2f640143` в ветке
`upgrade/proportionate-user-acceptance`. Кандидат r48 изменяет:

- `verification-delivery.md`: существующий Soft gate D выбирает достаточный
  метод по изменённому поведению, требует применимую сверку затронутой части
  исходно согласованного макета и отделяет недоделку от необязательной полировки.
  Итоговый отчёт различает реализацию и подтверждённый результат.
- `verification-policy.md`: существующий triage маршрутизирует к этому владельцу;
  размер задачи, расширение файла и full-cycle сами по себе не требуют UI.
- `sdd-integrations.md`: применимые критерии входят в существующие DoD/tasks,
  без отдельного документа или обязательного сохранённого сценария.
- `dev-standards-env.md`: `essential` использует эту же применимость, вместо
  требования основного сценария каждой изменённой формы/команды.
- `tools/validate-rules.ps1`: только измеренный лимит контекста, см. ниже.

ITL сохраняет владельцев классификации, допустимых методов, актуальности,
one-off receipt и итоговой готовности. Reference `verification-suite-selection`
связывает существующие obligations с уточнённым правилом; схема и код оценки
не меняются. Никакого автоматического включения UI или деплоя нет.

Прежние `manual`/`off`, именованный override, более широкий запрет UI,
provider policy, границы ИБ и утверждённая приёмка сохраняют приоритет.
Недоступное требуемое наблюдение оставляет соответствующий результат
непроверенным с конкретной предпосылкой; независимая работа продолжается.
Ни test count, ни screenshot-файл, ни checkbox не подменяют приёмку.

## Проверка применимости инструкции

Это разбор решений по инструкции, а не live-прогон нового агента или PM5.

| Случай | Достаточное решение |
|---|---|
| Исправлен расчёт, вывод и взаимодействие не менялись | Unit/integration/data proof ожидаемого значения; отдельное открытие формы не требуется. |
| Исправлена подпись или видимость поля | Осмотр затронутого элемента и нужных состояний; без полного обхода формы. |
| Исправлено открытие отбора | Проверить вызов и результат затронутого действия; не обходить остальные функции инструмента. |
| Новый инструмент с первым запуском и настройками | Основной путь до результата в целевом клиенте, включая отсутствие сохранённых настроек и представительные данные/роли, где затронуты. |
| Изменена карточка при согласованном макете доски | Сверить карточку и её договорённости при сравнимых условиях; не перепроверять неизменённую доску целиком. |
| Изменён серверный отказ по правам без изменения UI | Проверить разрешённый/запрещённый результат достаточным интеграционным методом; UI нужен при риске видимости, доступности или объяснения действия. |
| Макет существует, но изменён только внутренний алгоритм | Наличие макета само по себе не требует повторной визуальной сверки. |
| Требуемый UI-маршрут запрещён или недоступен | Сохранить непроверенный критерий и предпосылку; browser preview не объявлять нативным свидетельством. |
| Сценарий выполнен, предлагается иной цвет вне договорённостей | Необязательное улучшение; существенное несоответствие согласованному макету остаётся недоделкой. |
| После проверки исправлен один дефект | Повторить затронутое доказательство, сохранить актуальные независимые результаты; одинаковый сбой требует диагностики. |

## Стоимость контекста

Корневой AGENTS, описания навыков/агентов и runtime не меняются. Весь алгоритм
выбора и граница завершения остаются в одном уже загружаемом владельце.
Нормализованный full-cycle load set растёт с 138084 до 141300 UTF-8 байт:
+3216 байт, примерно 804 токена по bytes/4, не точный счётчик модели.
Существующий лимит повышен с 136 до 140 KiB; правила и проверки не сокращаются
ради бюджета. SDD и env остаются в прежних индивидуальных лимитах.
