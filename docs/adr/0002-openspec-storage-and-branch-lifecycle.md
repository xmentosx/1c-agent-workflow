# Хранилище OpenSpec выбирается отдельно от жизненного цикла ветки

Принято 2026-09-28 для миграции на upstream
`20a083e5bd9fa41402ad8428b740c4c01f0cc3d6` (решения Q10.1, Q11–Q12).
Поддержка внешних хранилищ входит в миграцию сразу; её реализация и проверка ещё
предстоят.

Локальные документы OpenSpec остаются полноценным вариантом по умолчанию как для
существующих, так и для новых проектов. Обновление не переносит их и не назначает
глобальное хранилище. Пользователь может впоследствии изменить выбор. Разрешение
адреса принадлежит OpenSpec CLI: поддерживаются явно выбранный store, проектная
привязка и настроенный пользователем глобальный defaultStore. Агент сообщает
фактический адрес и сохраняет выбранную область на протяжении задачи; ошибка
внешнего хранилища не разрешает незаметно создать локальную копию постановки.
Смена выбранного адреса сама по себе не означает перенос существующих документов.

Внешнее хранилище имеет самостоятельный жизненный цикл. Обновление ITL управляет
инструкциями и проектной привязкой; refresh, reset, закрытие ветки и восстановление
после неудачного обновления не откатывают, не удаляют и не архивируют его
постановки. Задача связывает выбранную постановку с рабочей веткой. Конкурирующие
изменения той же постановки согласуются перед записью. Локальные документы
продолжают участвовать в обычных Git-операциях своего проекта.

Ограничение только локальными документами исключило бы принятую возможность
общего хранилища. Автоматический перенос всех проектов и общий откат хранилища
вместе с веткой могли бы затронуть постановки других задач. Выбранная граница
сохраняет обе схемы, но означает, что возврат к старому коду не возвращает
автоматически старую редакцию внешних документов. Текущая проверка интеграции и
локальный snapshot должны быть адаптированы к этой границе; их действующий
контракт описан в [правилах обновления fork](../ai-rules-fork-upgrades.md).
