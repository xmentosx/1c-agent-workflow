# Доказательства проверки независимы от сохранения автотеста

Принято 2026-09-28 при разборе миграции `ai_rules_1c` с upstream
`410951e74fd3e6b7a763cf49757935b9a34d3f31` на
`20a083e5bd9fa41402ad8428b740c4c01f0cc3d6` (решения Q3, Q5–Q8).
Это согласованное направление изменения; действующая реализация ещё не переведена
на него.

Разделяем доказательство поведения в текущей задаче, сохранение регрессии для
будущего и периодичность её исполнения. Агент выбирает достаточную проверку по
риску и имеющемуся покрытию, а необходимость сохранять новый тест — по его
дальнейшей ценности. Даже для опасного дефекта это мотивированное решение агента,
а не обязательный отдельный запрос пользователю. Существующее достаточное
покрытие переиспользуется. Это сохраняет достоверность результата без накопления
дорогих тестов, повторяемых при каждой небольшой правке.

Разовая проверка может дать обычную готовность задачи, в том числе при политике
`block`, когда она действительно закрывает все применимые обязательства. Её
нельзя выдавать за успешный запуск отсутствующего набора тестов или оформлять
фиктивным `notApplicable`. Невыполненное обязательство остаётся непроверенным.
Для сохранённого дорогого теста отдельно выбирается обоснованная периодичность:
изменение затронутого поведения или значимая передача результата не равны каждому
быстрому прогону.

Запрет запуска не запрещает подготовку нужного теста. Явный разовый запрос на
конкретную проверку разрешает её в указанной области без постоянного изменения
настройки. Интерактивная UI-проверка и запуск сохранённых Vanessa-сценариев имеют
раздельные настройки; более широкий пользовательский запрет открывать UI
распространяется на обе области.

Альтернативы — обязательная новая регрессия для каждого изменения либо отказ от
планирования проверки вслед за запретом upstream планировать отдельные категории
тестов — не выбраны. Первая смешивает текущую уверенность с будущей стоимостью
сопровождения, вторая не доказывает правильность результата. Следствие решения:
классификация, готовность и восстановление должны различать реальные виды
доказательств; смены текста правил недостаточно. Текущий контракт описан в
[verification-result](../../.agents/skills/1c-workflow/references/verification-result.md).
