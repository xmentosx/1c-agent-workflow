# Состояние поиска и записи принадлежит Mantis MCP

28 сентября 2026 года пользователь выбрал отдельное состояние Mantis на существующем MCP-хосте: SQLite для локальных текстов, фильтров, контрольных точек и журнала операций, Zvec для векторов. Владельцем является Mantis MCP; общая очередь или общее состояние с Code, BookStack и lifecycle 1С не вводятся. Альтернативы — одно SQLite-хранилище с непроверенной скоростью полного перебора векторов или отдельный сервер БД — отвергнуты в пользу уже знакомого по Code сочетания, ценой обязанности согласовывать две локальные проекции и проверять восстановление после сбоя; Mantis остаётся источником исходных данных.

Выбор хранилищ не заменяет требуемый перед реализацией архитектурный checkpoint по совместимости, установленному состоянию, восстановлению и откату. Реализация и развёртывание этим решением не разрешены.

Для составных операций записи согласовано сохранять успешные шаги и продолжать только незавершённые вместо автоматического отката уже опубликованного. При потере ответа после возможного создания MCP сверяет результат с Mantis; если результат неоднозначен, повтор создания останавливается для разрешения ситуации. Выбор защищает от автоматических дублей ценой возможной ручной проверки и требует сохранять журнал операций независимо от перестроения поискового индекса; он не означает наличие общей транзакции или серверной идемпотентности Mantis.

Для выбранных пользователем эмбеддингов OpenRouter `qwen/qwen3-embedding-8b` согласованы учёт расходов и настраиваемый месячный предел, первоначально $5 для Mantis. При недоступности OpenRouter или достижении предела текстовый поиск, фильтры и поиск имён файлов сохраняются, новые эмбеддинги ожидают возможности обработки, а семантическая доступность и полнота показываются явно. Тем самым доступность текстового поиска не зависит от готовности векторной проекции; платная индексация в ходе grill не запускалась.
