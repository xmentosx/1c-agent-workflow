# Переносимость baseline обязательна для обычного on-demand-проекта

Принято 2026-10-04; файловый пилот предшествует отдельной серверной приёмке
по [плану](../on-demand-source-mode-implementation-plan.md).

Обычный on-demand-проект должен восстанавливать принятый baseline и состояние
веток на другом хосте после потери локального runtime, даже если источник
уже перешёл на другую ревизию. Поэтому необходимые исторические cursor,
содержимое и снимки имеют переносимый checkpoint с проверяемым provenance;
активные процессы, локальные подключения и секреты остаются локальными.
Однохостовая модель проще, но могла бы сделать неизменяемый on-demand-проект
невосстановимым, поэтому она допустима только как явно ограниченный пилот.

Сохраняются входы активных baseline и выбранных архивов, а не глобальная история
всех XML-версий. Формат, хранение и восстановление checkpoint должны пройти
эксперимент и приёмку до обычного включения; этот ADR не утверждает их готовность.
