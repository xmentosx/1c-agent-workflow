# Общий корпус СППР и граница внешней индексации

По решению пользователя от 2026-09-28 все пользователи СППР MCP имеют полный доступ к его корпусу; индивидуальное разграничение видимости объектов внутри MCP не выбирается. Для семантической индексации выбран OpenRouter с моделью `qwen/qwen3-embedding-8b`, поэтому список разрешённых проектов задаёт также границу допустимой передачи данных внешнему сервису: первоначально разрешён «Кейс проект PM5», а содержимое карточек других проектов передавать нельзя. Предложенный вариант локального построения эмбеддингов не выбран; расширение корпуса требует явного расширения разрешённого списка, а наличие связей с разрешённым объектом само по себе не разрешает передачу содержимого карточки другого проекта.

Доступ к источнику выполняется со стандартной аутентификацией 1С по отдельному логину и паролю. Учётные данные источника остаются вне Git, документов и поискового корпуса; выбранная учётная запись не задаёт индивидуальные права пользователей MCP. Ограничение работы сборщика открытым пользовательским сеансом на `dev-ermakov` сохраняется.

Пользователь подтвердил, что разрешён весь текст карточки выбранного проекта, включая заметки и вставленные цитаты. Вместе с карточкой допустимы необходимые значения общих справочных реквизитов, в том числе названия статусов, спринтов, разделов и имена разработчика или тестирующего; разрешение не распространяется на выгрузку общего справочника целиком.

В опубликованной схеме СППР решения, проблематики и функциональные решения не имеют собственного реквизита проекта. Пользователь разрешил включать их полное описание по явной цепочке связей из разрешённых объектов PM5, сохраняя основание включения каждого общего объекта. Это разрешение не распространяется на выгрузку всего общего справочника или карточек других проектов, связанных с тем же общим объектом. Под функциями в первоначальном корпусе понимаются функции системы; функции механизмов в него не входят.

Пользователь также согласовал передачу текста семантического поискового запроса в OpenRouter и потребовал кеширование вычисленных векторов запросов. При наличии совместимого вектора в кеше повторный запрос использует его; извлечение найденных карточек и обход записанных связей выполняются на стороне MCP. Согласован ограниченный кеш в памяти процесса по образцу Code MCP, до перезапуска; совместимость определяется моделью и параметрами построения вектора, а обновление содержимого СППР само по себе не требует пересчёта вектора запроса.
