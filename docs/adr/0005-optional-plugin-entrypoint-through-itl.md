# Необязательный плагин подключает проект через существующие операции ITL

Принято 2026-09-28 при подготовке миграции на upstream
`20a083e5bd9fa41402ad8428b740c4c01f0cc3d6` (решение Q18).
В объём миграции входит адаптированный плагин из controlled fork как
дополнительный способ подключения клиента. Реализация и квалификация ещё
предстоят; установленный плагин сам по себе не доказывает готовность проекта.

В управляемом проекте плагин вызывает существующие ITL-операции установки,
подключения клиента и обновления. ITL сохраняет владение bootstrap, базами,
MCP, условиями выполнения и восстановлением; используется закреплённая версия
компонентов проекта. Прямой upstream init/add/update, обходящий это владение,
не становится вторым механизмом управления тем же проектом.

Версия плагина в клиенте и версия правил конкретного проекта имеют разные
жизненные циклы. Обновление плагина не обновляет автоматически правила всех
проектов. Открытие папки само по себе не разрешает инициализацию workflow,
создание баз или независимое изменение управляемой установки. Для нового
проекта явный запрос на настройку workflow может запускать через плагин
существующий bootstrap; область операций определяется этим запросом.

Подключение дополнительного клиента сохраняет прежние подключения и общую
согласованную версию правил согласно [решению Q19–Q20](0004-multiple-clients-and-support-scope.md).
Отключение плагина сохраняет проектные правила и рабочие базы; обычные способы
работы с ITL остаются доступными. Ошибка подключения должна давать причину и
продолжение через существующего владельца восстановления, а не скрытый успех
или самостоятельный ремонт manifest агентом.

Выбранный вариант облегчает подключение и освоение workflow ценой поддержки
совместимости plugin-входа, проектных версий и клиентских механизмов. Принятие
обычного upstream-плагина без адаптации не обеспечивает закреплённый источник,
delegated MCP и ITL-восстановление; откладывание plugin-входа сохранило бы только
прежние способы установки. Плагин остаётся необязательным: поддержка клиента
через адаптер не означает наличия у него нативного plugin-механизма. Детальный
дизайн и проверки совместимости относятся к последующей постановке миграции.
